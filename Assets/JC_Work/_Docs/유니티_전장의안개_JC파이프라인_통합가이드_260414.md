## 1. 시스템 개요

플레이어·구조물 등 **Revealer**가 공개한 셀만 실시간 렌더, 그 외는 볼륨형 fog로 덮는 3D 전장의 안개 시스템.

핵심 특징:
- **URP Render Feature 기반 후처리 파이프라인**
- **GPU RT 2장** (Current R8 + Explored ARGBFloat), CommandBuffer + Blit
- **볼륨형 안개** (`_FogCeilingY` 기반 3레이어)
- **실시간 감쇠 복원** (5s 대기 → 1.5s에 걸쳐 3레이어 순차)
- **FogHidable Layer로 유닛 은폐** (stencil 기반 clip)
- **Unexplored vs Explored 차등 밀도** (지형 은폐 차이)

현재 턴제 게임 로직과 직접 연결은 없음. 실시간 기반이지만 `IFogTimeSource` 추상화로 턴 매니저 연결 가능 (D 작업에서 추가 예정 — 본 가이드 시점엔 미도입).

## 3. 렌더 파이프라인 순서

URP-JC-Renderer의 Feature 4종이 enqueue되어 아래 순서로 실행:

```
1. [URP 기본] DepthPrepass             ← FogHidable Layer 제외 (카메라 cullingMask)
2. [URP 기본] Opaque                   ← 지형·정적 오브젝트·Default Layer 유닛 렌더
3. [NEW]     FogStencilPrepassFeature  ← Fogged 영역 판정 → stencil=1 기록
4. [NEW]     FogHidableClipPassFeature ← FogHidable Layer 2차 cull → stencil≠1 통과만 렌더
5. [기존]    FogOfWarFeatureJC         ← 볼륨 fog color overlay (감쇠·cloud·volume)
6. [URP 기본] Transparent
7. [URP 기본] PostProcess
```

**중요**: 카메라의 `cullingMask`는 Layer 19(FogHidable)를 **제외**하도록 설정됨. 기본 Opaque에서 FogHidable 유닛이 그려지지 않고, 커스텀 Pass 4번에서 2차 Cull로 재수집 후 stencil 테스트를 거쳐 렌더.

## 4. FogHidable Layer 규약

**Layer 19 = "FogHidable"**. 이 Layer에 속한 Renderer는 Fogged 셀에서 stencil clip 대상.

### 현재 팀 Layer 맵 (TagManager.asset)

| index | 이름 | 용도 |
|---|---|---|
| 3 | Obstacle | 장애물 물리 |
| 6 | Item | 아이템 물리 |
| 7 | Mine | 광산 물리 |
| 8 | Player | 플레이어 물리 |
| 9 | Enemy | 적 물리 |
| 10-18 | (비어있음) | 여유 슬롯 |
| **19** | **FogHidable** | **렌더 전용 — fog 은폐 대상** |

### 원칙

- 부모 GameObject의 Layer는 **물리·AI·쿼리용** (Enemy/Player/Mine 등)
- 자식 Renderer GameObject의 Layer는 **FogHidable** (렌더링 전용)
- 한 GameObject는 한 Layer만 가질 수 있으므로 **자식 분리 필수**

## 5. 유닛 프리팹 구조 규약

### 표준 구조

```
Enemy (부모 GameObject)
  ├ Layer: Enemy (물리)
  ├ Collider, AI, Movement 스크립트
  ├ FogHidableTag 컴포넌트 ← 자식 Renderer들 Layer 자동 설정
  └ Visual (자식 GameObject)
      ├ Layer: FogHidable (렌더)
      └ MeshRenderer / SkinnedMeshRenderer
```

### `FogHidableTag` 컴포넌트

- `Assets/JC_Work/Scripts_jc/Manager/FogHidableTag.cs`
- 부모에 부착 → `GetComponentsInChildren<Renderer>()` 순회 → 자식들의 `gameObject.layer`만 FogHidable로 설정
- **부모 자신의 Renderer는 처리하지 않음** (부모는 물리 Layer 유지)
- `[ExecuteAlways]` + `OnValidate()` → 에디터에서 값 변경 즉시 반영

### 예외 — Fog에 영향 안 받는 유닛

Revealer로 등록된 아군 유닛(Player 등)은 FogHidable 태그를 **붙이지 않음**. Default Layer로 두면 항상 렌더. 또는 "자기 시야 안에서만 보이는" 처리가 필요하면 별도 설계.

### 검증 예시 (Mine1.prefab 등)

Mine1~4 프리팹은 이 구조로 만들어져 있음:
- 부모 Layer = Mine (물리)
- 자식 Cube Layer = FogHidable → fog에서 사라짐
- 자식 Cube Layer = Default → 항상 보임 (터레인 취급)

## 8. 감쇠·복원 타이밍 모델

```
시야 잃은 시점 (t=0)
│
├─ 0s     : Low/Mid/High 모두 visibility=1 (fog 없음)
│           → 유닛 렌더, 지형 fog 없음
│
├─ 5.0s   : Low 감쇠 시작
├─ 5.5s   : Low 감쇠 완료 (vis=0) + Mid 감쇠 시작
│           → stencil clip 활성 (fogHidableLowThreshold=0.05 이하)
├─ 6.0s   : Mid 감쇠 완료 + High 감쇠 시작
├─ 6.5s   : High 감쇠 완료 (모든 레이어 fog 완성)
│
└─ (유닛은 Low 감쇠 완료 시점(~5.5s)부터 숨겨짐)
```

### 가정 — 탐험 여부는 `explored.a`(elapsed time)로 판정
- `a = 0` → Unexplored (한 번도 안 본 곳)
- `a > 0` → Explored (탐험 후 refogged)

### 본 구조의 특징
- **게임로직 시야는 Revealer 결과(binary)**, 감쇠는 순수 시각 연출
- 턴 기반 전환 시 `restoreDelay`를 0으로 두고 FogTimeSource가 elapsed를 점프시키는 형태로 대응 가능 (미도입)

## 9. 확장·수정 포인트

### 튜닝만 필요한 경우 (비침습적)
- 시각 파라미터 → `FogOfWarMaterialJC.mat` Inspector
- 감쇠 타이밍 → `[GameManager].prefab`의 PlayFogManager Inspector

### 셰이더 로직 수정
- `FogOfWarJC.shader`에서 레이어 구조, Unexplored/Explored 분기, 구름 노이즈, volume ceiling 변경
- 수정 시 URP-JC-Renderer의 Feature Reset 필요할 수 있음

### 새 Render Pass 추가
- `ScriptableRendererFeature` 상속 → URP-JC-Renderer에 등록
- 기존 순서 영향 고려 (Stencil Prepass → Clip Pass 순서가 중요)

### 파이프라인 대체 구현 (포크)
- URP-JC-Renderer에서 기존 Feature 제거, 신규 Renderer Data 생성
- 카메라의 Renderer Override 변경
- 공용 Renderer를 건드리지 않도록 주의 (타 씬 영향)

## 10. 알려진 한계

| 항목 | 설명 | 대응 |
|---|---|---|
| **그림자 누출** | FogHidable 유닛은 ShadowCaster 패스에서 걸러지지 않아 Fogged 지형에 그림자가 드리울 수 있음 | ShadowCaster Layer mask도 FogHidable 제외 필요 (미구현) |
| **Transparent 유닛** | Opaque pass만 clip 대상. Transparent 유닛은 현재 미지원 | 필요 시 Transparent용 2차 clip pass 추가 |
| **맵 경계 밖 오브젝트** | `_GridWorldSize` 범위 밖 worldPos는 Fogged 취급 (stencil=1) → 항상 clip됨 | 맵 경계 밖에 FogHidable 배치 금지 |
| **탐험 판정의 세분도** | `explored.a > 0` 1 픽셀이라도 있으면 Explored → 낮은 해상도 RT에서 경계가 애매할 수 있음 | 그리드 해상도만큼의 정확도. 현재 64×64 기본 |
| **3D 시점 일관성** | Fogged 영역의 지형은 "현재 시점" 기준으로 렌더됨 (StarCraft식 "최후 스냅샷"이 아님) | 설계 시 의도적 — 3D에서 스냅샷 대안이 부적합 |
| **카메라 cullingMask 의존** | 해당 카메라가 URP-JC-Renderer를 쓰고 cullingMask에서 FogHidable 제외해야 정상 동작 | 새 씬에서 카메라 Renderer + Layer Mask 확인 필요 |

## 11. 다른 팀원 접점

### DH (월드맵·레벨에디터·그리드)
- **Revealer 추상화 도입 예정** — `IFogRevealer` 인터페이스 + `FogRevealerRegistry`. DH의 `PartyFogRevealer`/`MineFogRevealer` 패턴이 표준화 대상
- **TurnManager 연결** — `IFogTimeSource` 구현체 추가로 턴 기반 감쇠 트리거 가능
- **그리드 통합** — DH의 GridManager와 JC의 PlayGridManager 머지 시 fog 시야 갱신 API 경로 재설계 필요

### KJ (플랜 A 셰이더·전장의 안개)
- 셰이더 3종(FogOfWarJC/FogMaskJC/FogDecayJC)은 JC 플랜 B 구현. 플랜 A 구현 시 이 자산을 참조 또는 대체
- 파이프라인 경계(FogStencilPrepass + FogHidableClip)는 Fog 구현 방식과 무관하게 재사용 가능 — Visibility 텍스처 글로벌 2종(`_VisibilityCurrentTex`, `_VisibilityExploredTex`)만 유지되면 됨
- 플랜 A로 전환 시 URP-JC-Renderer의 FogOfWarFeatureJC만 교체, Stencil/Clip Feature는 그대로 유지 권장

### ASB (전투 시스템)
- 전투 유닛(적·아군) 프리팹 제작 시 **5장 규약**을 따라 `부모=Enemy/Player` + `자식=FogHidable` 구조 준수
- `FogHidableTag` 컴포넌트를 유닛 베이스 클래스 프리팹에 부착해두면 팀원이 매번 설정 불필요

## 부록 A — 핵심 Global Shader Variables

PlayFogManager가 `cmd.SetGlobalTexture`/`SetGlobalVector`/`SetGlobalFloat`로 전역 설정. 다른 셰이더에서도 동일하게 참조 가능.

| 이름 | 타입 | 의미 |
|---|---|---|
| `_VisibilityCurrentTex` | Texture2D (R8) | 현재 시야 마스크 |
| `_VisibilityExploredTex` | Texture2D (ARGBFloat) | 레이어별 visibility + elapsed |
| `_GridWorldSize` | float4 | (worldW, worldH, 1/worldW, 1/worldH) |
| `_RestoreDelays` | float4 | (lowDelay, midDelay, highDelay, 0) |
| `_RestoreDuration` | float | 레이어 공통 감쇠 소요 |
| `_FogDeltaTime` | float | 프레임 dt (FogTimeSource용 훅) |

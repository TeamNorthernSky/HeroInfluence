# JC 수로 수면 셰이더 기술문서

작성: 2026-10-10 · Unity 2022.3 / URP 14 · JC_Testbed

## 목적과 적용 범위

탐사씬의 타일 구조를 유지하면서 수면이 하나의 이어진 물처럼 보이게 한다. 반복되는 흰 무늬 대신 불규칙한 표면 기울기와 반사로 잔물결을 표현한다. 수로의 방향에 맞춘 흐름은 시각 연출이며 유체 시뮬레이션이나 이동 판정이 아니다.

관리 위치는 `JC_WorldDressing > JC_ExploreDetail`이며 설정은 `JcExploreDetailProfile`이다. 원본 DH 타일 데이터, 충돌체, 이동 가능 영역을 수정하지 않는다. 오버레이를 끄면 원본 렌더링을 복원한다.

## 구성 파일

| 파일 | 역할 |
|---|---|
| `Environment/ExploreDetail/CalmCanalWater.shader` | 불규칙 물결, 흐름, 반사, 물가 색 |
| `JcExploreDetailOverlay.WaterFlow.cs` | 수로 연결 분석과 공통 방향 텍스처 생성 |

| `CanalBank.shader` | 콘크리트 호안의 이음매와 젖은 부분 |
| `JcExploreDetailProfile.cs` | 인스펙터 설정 |
| `Resources/JC_ExploreDetail_Default.asset` | 기본 설정과 셰이더 참조 |

경로는 `Assets/_ProtoType_Merge/JC` 기준이다. 생성 메시·머티리얼·방향 텍스처는 임시 자원이며 `Restore()`에서 해제한다. 프로필만 영구 설정 에셋이다.

## 타일 사이를 연속적으로 보이게 하는 방식

물결 좌표는 타일마다 0~1로 시작하는 UV가 아니라 **월드 X/Z 좌표**다. 모든 수면 렌더러가 동일한 머티리얼, 시간, 방향 텍스처를 공유한다. 같은 위치는 같은 물결 계산을 거치므로 청크 경계에서 무늬가 다시 시작하지 않는다. 메시를 거대한 한 장으로 합칠 필요는 없다.

UV0는 원본 표시를 위한 좌표로 유지한다. UV1.x에는 완성된 호안 끝에서 수면 안쪽까지의 거리를 기록하여 물가 색에 사용한다. UV1.y는 호안의 상단~하단 구분 값이다.

## 수로 방향 지도

1. 원본 타일에서 물 셀을 수집한다. 교량 밑에 시각적으로 추가한 물 셀도 포함한다.
2. 높이가 일치하고 상하좌우로 연결된 물을 하나의 수역으로 나눈다.
3. 각 수역에서 `Water Flow Direction` 방향으로 가장 먼 셀을 하류 기준으로 선택한다. 동일 점수는 좌표 순서로 결정하여 재생성 결과를 안정적으로 유지한다.
4. 하류까지 수로 내부를 따라 이동하는 셀 거리를 너비 우선 탐색으로 구한다. 거리 감소 방향으로 초기 흐름을 계산한다.
5. 연결된 이웃끼리 8회 평균을 내어 굽은 곳의 방향을 완만하게 연결한다. 물가에서는 경계에 수직인 성분을 억제하여 흐름이 육지로 향하는 현상을 줄인다. 이 과정에서 물가 속도도 낮아진다.
6. 방향 X/Z를 RG에 0~1로 인코딩한다. 텍스처는 RGHalf, 선형 색 공간, bilinear 보간, Clamp이며 mipmap은 없다. 월드 좌표에서 텍셀 중심으로 정확히 대응하도록 반 셀 여백을 반영한다.

지도 밖의 여백은 인접 방향으로 채운다. 한 축이 1024텍셀을 초과하면 경고와 함께 공통 방향으로 복귀한다. 현재 방식은 동일 크기의 수평 타일을 전제로 하며, 서로 다른 높이의 수면이 X/Z상 겹치거나 셀 크기가 혼합된 맵에는 별도 분리가 필요하다.

## 흐름과 잔물결 계산

`WaterNoise()`는 정수 격점의 해시 값과 5차 보간으로 불규칙한 높이 및 기울기를 만든다. 서로 다른 크기와 회전의 큰 물결 두 겹, 작은 잔물결 두 겹을 사용한다. 큰 저주파 무늬로 좌표를 조금 비틀어 규칙적인 격자 느낌을 줄인다. 작은 물결은 화면 미분값으로 멀리서 감쇠시켜 반짝임을 줄인다.

위치별 방향으로 좌표를 무한히 이동시키면 굽은 곳에서 무늬가 계속 늘어난다. 이를 막기 위해 제한된 거리만 이동하는 두 위상을 교차 혼합한다.

```text
span = max(0.25, 큰 물결 크기 × 0.75)
phaseA = frac(시간 × 흐름 속도 / span)
phaseB = frac(phaseA + 0.5)
이동 좌표 = 월드 XZ − 지역 흐름 방향 × phase × span
B 혼합 비율 = abs(phaseA × 2 − 1)
```

한 위상이 처음으로 되돌아갈 때 해당 위상의 가중치는 0이므로 갑작스러운 위치 점프를 숨긴다. B 위상에는 별도 좌표 오프셋을 사용한다. 자체 잔물결은 서로 다른 두 월드 방향으로 연속 이동한다. 두 위상은 표면 기울기, 큰 색 변화, 물결 음영 값을 혼합한다.

이 방식은 변형을 제한하는 시각적 근사다. 분기점에서 물의 양을 보존하거나 소용돌이를 계산하지 않으며 매우 긴 관찰에서는 위상 반복을 느낄 수 있다. 물결 기울기도 좌표 왜곡 전체의 엄밀한 미분이 아닌 반사 연출용 근사다.

## 색·빛·그림자

흰 선을 수면에 직접 그리지 않는다. 합성한 기울기로 표면 법선을 만들고 URP 환경 반사, 프레넬, 주광원의 약한 반사광을 계산한다. 물가 거리로 중앙색과 가장자리색을 섞는다. 큰 물결과 잔물결의 기울기에서 별도의 유색 밝기 음영을 계산하여 반사광이 약한 구도에서도 움직임을 보여준다. 추가 밝기는 원래 물색의 -40%~+50%로 제한하며, 주광원 그림자와 안개를 유지한다.

현재 수면은 **불투명**, 깊이 쓰기 켜짐, 뒷면 제거 방식이다. 굴절, 수중 물체 투시, 실제 파도 높이 변화, 교각 충돌 물보라는 없다. 환경 반사는 조명의 영향을 받지만 추가 물결 음영은 반사 설정과 독립적이다.

## 인스펙터 조절

| 설정 | 의미 |
|---|---|
| Cartoon Water | 수면 셰이더 교체 |
| Water Follow Canal | 수로별 방향 지도를 사용. 끄면 공통 방향 |
| Water Flow Direction | 켜짐: 하류 선택 기준. 꺼짐: 월드 X/Z 이동 방향 |
| Water Flow Speed | 흐름 이동 속도. 0은 이류 정지이며 잔물결은 별도 |
| Water Wave Size / Strength | 큰 물결 크기 / 기울기 강도 |
| Water Wave Visibility | 큰 물결의 추가 음영 가시성. 0~3, 기본 1. 기울기 강도와 함께 작용 |
| Water Ripple Size / Strength / Speed | 작은 잔물결 크기 / 강도 / 자체 일렁임 속도 |
| Water Ripple Visibility | 잔물결의 추가 음영 가시성. 0~3, 기본 1. 반사 강도와 독립 |
| Water Flow Variation | 약한 색 변화. 직렬화 필드명은 기존 `waterFlowStreakStrength` 유지 |
| Water Tint / Edge Tint | 중앙 / 물가 색 |
| Water Shine | 환경 반사와 반사광 강도 |
| Water Edge Width | 물가의 약한 밝기 띠 폭 |

완전히 정지시키려면 Flow Speed와 Ripple Speed를 모두 0으로 설정한다. 채도는 Tint 두 색에서 조절한다. 흐름 변경은 프로필 갱신에 따라 지도를 재생성하며 매 프레임 CPU에서 계산하지 않는다.

## 호안·교량과 복원

수면 주변 육지 경계를 이용해 콘크리트 상단, 경사면, 하단을 분할한다. 호안에 가려지는 원본 수직 벽은 복제 메시에서만 제거한다. 교량은 이름 및 렌더러 범위와 양쪽 물 셀을 검사하여 아래 연결 수면을 만든다. 도로 윗면과 충돌체는 유지하고 시각적 하부만 얇게 바꾼다. 복원 시 원본 렌더러 상태를 되돌리고 생성 자원을 제거한다.

## 성능과 확장 시 주의

방향 지도는 생성 시 CPU 작업이고 셰이더는 픽셀당 지도 1회 조회와 두 위상의 절차적 노이즈 계산을 한다. 이전 단일 위상보다 노이즈 계산량이 증가하므로 목표 기기의 GPU 프로파일링이 필요하다. 방향 지도는 직사각형으로 할당되어 떨어진 수역이 많으면 빈 공간 비용이 커진다. 현재는 화면 품질 확인용 테스트베드 구현이다.

실제 유입구·유출구가 기획으로 확정되면 자동 하류 선택 대신 수역별 출구 앵커와 방향 가이드를 추가할 수 있다. DH의 맵 배치 구조를 변경할 필요 없이 오버레이 쪽에 확장한다.

## 이번 검증 결과

- Unity C# 및 수면 셰이더 컴파일 오류 없음.
- 방향 지도 84×42, 수면 렌더러 16개에 공통 머티리얼 1개. 교량 하부 18셀 포함.
- 가로 수로·세로 수로·교량 아래 방향을 수치 확인.
- 호안/수면 4개 조합, 전체 표시 3회 OFF/ON, 컴포넌트 비활성 복원 통과.
- 원본 메시·머티리얼 참조 284개와 MeshCollider 참조 73개 보존 확인.
- Edit 모드 정적 렌더와 시간 오프셋 렌더에서 무늬 변화 확인. 이 검사는 체감 자연스러움이나 목표 기기 프레임 성능을 보장하지 않는다. 플레이 모드에서 속도와 강도는 추가 시각 평가가 필요하다.
- 플레이 모드 전환 및 씬 저장 없이 검사했다.

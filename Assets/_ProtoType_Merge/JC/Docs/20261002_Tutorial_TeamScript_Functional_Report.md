# 튜토리얼 적용을 위한 ASB·DH·KJ 스크립트 변경 리포트

작성일: 2026-10-02 · 비교 기준: main 반영 후 JC `8c1e8d3c` 대비 이번 튜토리얼 변경.

## 1. 이번 변경의 목적과 범위

탐사에서 첫 전투까지 기존 튜토리얼 진행 구조에 안내 연출을 연결하면서 발견한 **스킬 선택 불가, 결과창 정보 누락, 안내 밖 이동 허용**을 수정했다. 담당 영역의 스크립트를 수정한 이유는 아래 세 기능을 실제 게임 데이터와 맞추기 위해서다.

| 플레이 중 문제 | 적용 후 동작 | 관련 담당 영역 |
|---|---|---|
| 튜토리얼 영웅은 생성되지만 새 UI에서 스킬을 고를 수 없었음 | 튜토리얼 전용 데이터로 스킬·코어·설명을 함께 구성하고 실제 사용 가능한 스킬만 선택 | ASB, DH, KJ |
| 승리 결과에 물음표 초상화와 빈 수치가 표시됨 | 실제 튜토리얼 참가자의 초상화·레벨·EXP·현재 IP를 표시 | ASB, KJ |
| 첫 두 번 이동 후 자원 수집 단계에서 다른 블록을 자유롭게 선택할 수 있었음 | 현재 안내하는 위치만 경로 표시·이동 확정 가능 | DH |

아래 9개 스크립트가 담당 영역 변경의 전부다. 안내 상자·화살표·수렴 글로우·목표 라벨 연결은 JC의 신규 튜토리얼 연출 코드와 두 튜토리얼 씬에서 담당한다. 최신 main의 모델/스탯 인덱스 분리와 데이터 업데이트 등 팀원 변경은 이번 수정 실적으로 계산하지 않는다.

## 2. ASB — 튜토리얼 전투 데이터와 결과 표시

### 스킬·코어를 튜토리얼 데이터로 장착

**기존 문제:** 튜토리얼 영웅 생성에는 튜토리얼 전용 카탈로그가 쓰이지만 장착 단계에서는 일반 게임 카탈로그를 조회했다. 일반 데이터가 준비되지 않은 튜토리얼 환경에서 스킬 후보와 코어가 비어 새 UI로 선택할 수 없었다.

**변경된 사양:** 실제 튜토리얼 전투에 등록된 아군은 전용 카탈로그에서 현재 레벨에 맞는 스킬과 기본 코어를 받는다. 같은 계열의 상위 스킬을 배울 레벨이면 기본판 대신 상위판 하나를 선택한다. 스킬은 전투용 복사본으로 사용하여 공용 원본을 직접 바꾸지 않는다. 일반 전투와 적은 기존 데이터 경로를 유지한다.

- `BattleCharactor.PersistenceEquipment.cs`: 튜토리얼 아군 식별, 전용 스킬·코어 장착 및 UI가 확인할 수 있는 구분 상태 추가.
- `BattleCharactor.cs`: 튜토리얼 스킬 선택 시 일반 연구소의 강화값으로 전용 스킬 설정을 덮어쓰지 않도록 처리.

**팀에서 유지할 조건:** 튜토리얼 영웅은 전투 컨텍스트에 등록되어 있어야 하며 전용 카탈로그가 제공되어야 한다. 일반 저장 데이터의 보유·강화 상태에 따라 튜토리얼 스킬 구성이 달라지지 않아야 한다. 이번 작업은 스킬 피해 공식이나 레벨 성장 규칙의 재설계가 아니다.

### 실제 참가자 정보로 승리 결과 표시

**기존 문제:** 튜토리얼은 일반 보상을 주지 않으므로 결과 UI에 데이터 자체를 전달하지 않았다. 공용 결과창은 표시할 참가자 정보까지 잃어 초상화와 수치가 비었다.

**변경된 사양:** 전투 종료 시 실제 아군의 정보를 모은 **표시 전용 결과 데이터**를 전달한다. 참가 영웅 이름·초상화 식별 정보, 현재 레벨·EXP와 최대 EXP, 현재 IP를 표시한다. EXP 보상은 0이며 레벨·EXP의 전후 값은 같다. IP는 전투 종료 시점의 현재값을 전후 동일하게 전달하므로 획득량은 0이다.

- `BattleSceneManager.cs`: 튜토리얼 참가자 정보로 결과 표시 데이터를 구성하여 기존 결과창에 전달.
- `BattleRewardPlan.cs`: 결과 항목에 일반 보유 유닛 저장소 없이도 초상화를 찾을 수 있는 유닛 템플릿 키 추가.

**팀에서 유지할 조건:** 이 데이터는 화면용이다. 표시를 위해 일반 보상 지급·EXP 가산·IP 가산이나 일반 저장소 쓰기를 실행하지 않는다. 기존 튜토리얼 진행 저장과 탐사 복귀 흐름은 그대로 사용한다. 일반 전투의 보상 계획과 모의 전투의 처리도 기존 분기를 유지한다.

## 3. DH — 전용 스킬 조회와 안내 위치 이동 제한

### 튜토리얼 카탈로그를 새 전투 UI가 사용할 수 있게 연결

`TutorialCatalog.cs`에 현재 영웅·레벨에 맞는 스킬 목록과 기본 코어의 전투용 데이터를 제공하는 기능을 추가했다.

- 실제 전투용 목록에는 습득한 스킬만 포함한다.
- UI용 조회에서는 아직 배우지 않은 기본 스킬도 함께 제공하여 네 칸의 잠금 상태를 표시할 수 있다.
- 기본판과 상위판은 같은 계열로 묶어 중복 표시하지 않는다.
- 코어는 튜토리얼 테이블의 기본 능력치·효과·대상·비용을 복사하며 일반 장비 저장소의 강화값을 가져오지 않는다.

**팀 영향:** ASB의 실제 장착 목록과 KJ의 화면 목록이 같은 전용 데이터를 사용한다. 튜토리얼 영웅·스킬·코어 테이블을 변경할 때, 잠긴 스킬 표시와 실제 사용 가능 목록이 함께 바뀐다. 테이블 원본이나 전투 밸런스 수치는 이번에 변경하지 않았다.

### 현재 안내하는 블록만 이동 대상으로 허용

**기존 문제:** 원래 지정된 두 이동 단계가 끝나면 허용 목록이 비었고, 빈 목록에서는 모든 칸을 허용하는 설정으로 돌아갔다. 자원 수집 안내 중에도 다른 블록의 경로를 선택할 수 있었다.

**변경된 사양:** 기존 이동 제한 기능에 JC 안내가 현재 목표를 전달한다. 최초 두 목표, 이동력 소진 체험용 목표, 현재 수집할 자원, 빌런 접근 목표에 같은 제한을 적용한다. 설명 확인이나 턴 종료처럼 이동 목표가 없는 안내 단계에서는 이동 선택을 허용하지 않는다.

- `TutorialMovementConstraint.cs`: 기존 목표 목록을 안내가 읽을 수 있게 공개하고, 원본 단계와 별도로 현재 안내 목표를 일시 적용하는 기능 추가.
- `MoveCommandPreviewController.cs`: 경로 선택 시 안내 목표를 검사하고, 실제 이동 확정 직전에도 다시 검사.

**세부 동작:**

| 상황 | 동작 |
|---|---|
| 안내하지 않은 블록 클릭 | 새 경로를 표시하지 않고 기존 미리보기를 정리하며 이동하지 않음 |
| 목표 선택 후 안내 목표가 변경됨 | 이전 목표의 미리보기로 이동을 확정할 수 없음 |
| 이동력이 0인 체험 단계 | 지정 목표의 붉은 경로를 확인할 수 있지만 실제 이동은 불가 |
| 빌런을 클릭함 | 빌런 칸을 안내 대상으로 검사한 뒤 기존 시스템이 접근 가능한 위치로 경로를 계산 |
| 안내가 종료되거나 비활성화됨 | JC가 걸었던 일시 제한을 해제하고 기존 이동 제한 규칙으로 복귀 |

**팀에서 유지할 조건:** 원본 이동 단계 목록·현재 순서·저장 진행은 안내 표시에 맞추어 덮어쓰지 않는다. 이번 제약은 JC 안내가 담당하는 첫 전투 전 탐사 구간에 연결되어 있다. 이후 별도 플로우에서 새 이동 안내를 추가한다면 그 목표도 같은 제한에 연결해야 한다. 일반 탐사에 튜토리얼 제약을 적용하지 않는다.

## 4. KJ — 실제 사용 가능한 스킬 UI와 결과 초상화

### 보이는 스킬과 실제 사용 가능한 스킬을 일치시킴

`SkillButtonController.cs`는 튜토리얼 영웅의 네 스킬 칸을 전용 카탈로그로 구성한다. 습득 레벨을 충족해도 실제 전투 유닛의 사용 가능 목록에 없는 스킬은 버튼을 활성화하지 않는다. 이 확인은 일반 전투에도 적용되므로, 일반 UI에 이름이 표시되어 있다는 이유만으로 연결되지 않은 스킬 버튼이 활성화되지는 않는다.

튜토리얼 설명창은 실제 선택된 스킬·코어의 설명과 계수를 사용한다. 동일한 ID의 일반 템플릿이나 일반 강화값이 튜토리얼 설명을 덮어쓰지 않는다. 일반 전투의 설명 조회 경로는 유지한다.

**팀에서 유지할 조건:** 스킬 표시와 실제 장착 후보를 함께 갱신해야 한다. 버튼 활성화 검사를 단순히 레벨 조건만으로 되돌리면 표시되지만 선택되지 않는 문제가 재발할 수 있다. 기존 행동 제약·자동전투 시 수동입력 차단·선택 취소·대상 선택은 그대로 사용한다.

### 일반 보유 목록에 없는 튜토리얼 영웅의 초상화 표시

`HeroInfoResult.cs`는 결과 항목에 템플릿 키가 있으면 그 키로 초상화를 찾고, 없으면 기존 보유 유닛 인덱스 경로를 사용한다. 따라서 일반 저장소에 등록되지 않은 임시 튜토리얼 참가자도 초상화를 표시할 수 있다.

EXP·랭크·IP의 기존 결과 연출과 확인 버튼의 결과 확정 흐름은 재사용한다. 튜토리얼의 추가 보상이 0이라는 사양은 ASB에서 전달하는 표시 데이터로 표현한다.

## 5. JC 안내·씬 변경과의 연결

이 부분은 위 담당 스크립트 수정의 사용 맥락이다.

1. 첫 이동 안내는 강조 상자로 표시하고 시간 경과 또는 한 번 클릭으로 닫는다. 현재 목표는 우측 기존 퀘스트 양식에 남는다.
2. 두 번 이동하는 동안 선택 → 경로 표시 → 재클릭 이동 순서를 유지한다. 두 번째 안내에서 이동력 UI를 강조한다.
3. 지정 목표를 눌러 이동불가 경로를 확인한 다음 소진 설명과 턴 종료를 안내한다.
4. 필드의 실제 자원 종류·수량으로 수집 안내와 보유량을 표시하고 현재 자원 목표만 이동 허용한다.
5. 기존 전투 진행에 새 전투 UI·카메라 구성을 맞추고, 위 전용 데이터 연결로 스킬을 선택한다.
6. 결과 안내가 뜬 동안 화면 입력을 막으며 3초 경과 또는 한 번 클릭 후 안전하게 해제한다. 안내를 닫는 클릭이 결과 확인에 함께 전달되지 않도록 하고, 이후 확인 버튼을 강조한다.

공통 강조는 청록색이며 방향 화살표는 수직·수평으로만 표시한다. 화살표는 진행 방향으로 세 번 스윕 후 사라지고, 버튼 수렴 글로우는 2초 표시·1초 휴식을 반복한다. 월드 이동 목표는 별도의 파란 바닥 표식과 금색/파란 보석 화살표를 사용한다.

씬 단순 배치를 유지하며 프리팹화는 보류했다. 나무 배치 기능은 연결했지만 나무는 생성하지 않는다. 건물 실루엣은 가림 건물 반투명 처리이며 건물 부위별 색상 편집과는 다른 기능이다.

## 6. 확인 범위와 남은 사항

사용자는 탐사 이동부터 첫 전투 종료까지의 작동을 확인했다. 이후 피드백에 따라 안내·목표 제한·결과 표시를 보완했으며, 최신 main 반영 후 전용/일반 스킬 선택, 탐사 안내 단계, 결과 표시·입력 차단을 편집 모드에서 재검증했다. 후속 연출 전체의 플레이 검수 완료를 뜻하지는 않는다.

히어로톡 연결, 로비·홍보 튜토리얼, 첫 전투 이후 미완성 플로우와 별도 보상 설계는 이번 완료 범위가 아니다. 이전 씬 점검에서 확인한 DataManager의 Missing Script 및 일반 DataStorage 일부 누락 참조는 이번 전용 데이터 연결과 별개이며 정리 대상이다. 리포트는 전체 튜토리얼이 기획서의 모든 구간까지 완성되었다는 의미가 아니다.

# 전투 카메라와 UI 연결

확인일: 2026-10-13 · JC_Testbed 작업 트리 기준 · [문서 안내](README.md)

## 목적

카메라와 UI는 배경 생성 성공 여부와 별도로 적용하는 공통 표시 기능입니다. 테스트씬에서 정한 구도를 본게임과 튜토리얼에서도 재사용하고, 공간 부족으로 동적 배경 생성이 실패해도 기존 배경에서 공통 뷰를 사용할 수 있도록 연결했습니다.

캐릭터 턴·스킬마다 작동하는 다이나믹 연출 카메라는 후속 작업입니다. 현재 구현된 것은 프로필 기반 구도 전환과 실시간 조절이며, 새로운 전투 판정 규칙을 추가하지 않습니다.

## F6·F7·F8의 의미

| 키 | 표시 | 저장 관계 |
|---|---|---|
| F6 | 구도 A, 아군 중심의 기본 검토 구도 | 프로필 A |
| F7 | 구도 B, 반대 진영 확인용 구도 | 프로필 B |
| F8 | 해당 전투씬의 기존 기본 뷰 | 진입 시 보관한 원래 카메라 상태 |

F8은 구도 A/B를 덮어쓰는 저장 대상이 아닙니다. 테스트씬의 현재 위치 캡처는 A/B에서만 허용하며 전환 중에도 제한합니다. 프로필 B는 독립 저장값입니다. A를 수정할 때마다 자동 대칭으로 계속 갱신되는 것으로 가정하지 마세요.

실전 구도 이동은 기본 0.65초 동안 위치·회전·FOV를 보간하며 `unscaledDeltaTime`을 사용합니다. 위치는 `Vector3.Lerp`, 회전은 `Quaternion.Lerp`입니다. 순간이동 없이 이동하지만 회전의 수학적 각속도가 일정한 방식은 아닙니다.

## FOV와 Perspective Strength

FOV를 좁히기만 하면 화면이 확대됩니다. 현재 원근 보정은 FOV를 좁히는 동시에 카메라를 뒤로 물려, 기준 중심의 크기를 가능한 한 유지하면서 멀리 있는 진형이 지나치게 작아지는 느낌을 줄입니다.

저장 위치를 `P`, 전방 단위벡터를 `F`, 전투 중심까지 전방 깊이를 `d`, 원근 강도를 `s`라고 하면 다음과 같습니다.

```text
실제 위치 = P - F × d × (1/s - 1)
실제 FOV = 2 × atan(tan(저장 FOV / 2) × s)
```

`s=1`이면 저장 구도 그대로이며, 작아질수록 망원에 가까운 구도가 됩니다. 직교 카메라 전환은 아닙니다. 프로필의 강도 범위는 0.2~1, FOV는 10~100도입니다. 전투 중심이 카메라 전방에 있지 않아 깊이가 너무 작으면 보정하지 않는 방어 처리가 있습니다.

따라서 프로필에 보이는 위치·FOV와 실제 Camera 컴포넌트의 값이 다른 것은 정상일 수 있습니다. 캡처 시에는 역변환하여 저장하므로 저장할 때마다 카메라가 계속 뒤로 밀리는 누적 보정을 피합니다. 이 역변환을 우회해 실제 위치를 그대로 프로필에 대입하지 마세요.

## 플레이 중 조절과 영구 저장

테스트씬은 프로필을 편집용 임시 상태로 복사해 사용합니다. 위치·회전·FOV·Perspective Strength를 수정하면 현재 구도에 반영됩니다. 다음 세 행위는 구분해야 합니다.

1. **수치 편집:** 임시 A/B 구도 값을 직접 수정합니다.
2. **현재 카메라 캡처:** 프리카메라로 움직인 실제 Camera 상태를 A 또는 B의 임시 값으로 옮깁니다. F8에서는 하지 않습니다.
3. **카메라 프로필 저장:** 임시 A/B 값을 영구 `.asset`에 저장합니다. 단순히 프리카메라만 움직이고 저장 버튼을 눌렀다고 현재 Camera가 자동 캡처되는 것은 아닙니다.

프로필 로드는 저장된 값으로 임시 상태를 되돌립니다. 일반 전투 테스트 프로필 저장과 카메라 프로필 저장도 서로 다른 동작입니다. 플레이 종료 전 저장 대상을 확인하고, 종료 후 같은 에셋을 다시 읽어 반영 여부를 확인하세요. 씬 저장만으로 플레이 중 임시 구도가 영구 저장된다고 생각하면 안 됩니다.

본게임·튜토리얼은 같은 Resources 프로필을 읽지만 이미 생성된 실전 표시 객체가 외부 저장값을 언제 다시 읽는지는 별개의 문제입니다. 공유 변경 확인은 **새 전투 진입으로 재검증**하는 것이 명확합니다. 배포 실행에는 빌드 당시 에셋이 들어가므로 Editor에서 저장한 새 구도를 배포하려면 다시 빌드해야 합니다.

## HUD 레이아웃

캐릭터 정보·스킬 버튼·설명을 좌측 세로 패널로 옮기고, 턴 순서는 중앙 상단에 둡니다. 메뉴·자동·배속·도주 버튼은 우측에 유지하며 크기를 줄였습니다. 카메라 구도 버튼은 우측 상단에 작게 배치합니다. 두꺼운 장식을 줄이고 어두운 반투명 패널을 쓰는 방향이며, 최종 아트 리소스 교체는 보류 상태입니다.

`JcBattleHudLayout`은 기존 계층 경로로 RectTransform을 찾아 배치와 스타일을 변경합니다. 전투 버튼의 기존 이벤트·스킬 로직을 새로 만드는 방식은 아닙니다. 다만 경로가 바뀌면 적용 대상이 조용히 누락될 수 있으므로 프리팹 계층 변경 시 레이아웃 설정도 함께 확인해야 합니다.

설명 영역의 ScrollRect·Viewport를 구성하는 코드가 있으므로 `Apply`를 반복 호출하는 상시 갱신 함수처럼 사용하지 마세요. 반복 적용의 안전성은 별도 검증 대상입니다. 해상도 대응 역시 배치 설정 확인과 실제 여러 해상도 플레이 검증을 구분해야 합니다.

## 인질 HP바

인질은 공통 바 디자인을 이용하되 폭·두께를 줄이고 튜토리얼 계열 녹색 테두리(`#19FF54`)를 사용합니다. HP만 표시하며 IP와 불필요한 손실 표현은 끕니다. 현재 크기 보정은 일반 바 대비 0.85 기준이며 화면 높이에 따른 크기 계산을 사용합니다.

표시 그래픽의 Raycast를 막지 않게 처리하고, 카메라 투영과 깊이에 따라 위치·표시 여부를 계산합니다. 인질의 실제 체력·피해·구출 규칙은 기존 전투 시스템이 담당합니다. 프로필의 `unitBarPrefab` 연결과 ASB 쪽 인질 표시 연결을 함께 확인해야 하며, JC 바 프리팹만 수정했다고 모든 인질 경로가 검증되는 것은 아닙니다.

표시 구현은 [HostageHPBar](../../../ASB/Scripts/Battle/Scenario/HostageHPBar.cs)와 [HostageBattleActor](../../../ASB/Scripts/Battle/Scenario/HostageBattleActor.cs)를 함께 확인합니다.

## 수정 후 확인할 항목

- 새 전투 진입 시 공유 프로필 A가 적용되는지, F6/F7/F8 이동과 원래 뷰 복귀가 정상인지 확인합니다.
- 프리카메라 캡처 → 프로필 저장 → 플레이 종료 → 다시 진입 순서로 영구 저장을 확인합니다.
- FOV·원근 강도를 함께 바꾼 뒤 캡처를 반복해 위치가 누적 이동하지 않는지 확인합니다.
- 일반 이벤트·아놀드·점령전·튜토리얼 각각에서 배경과 UI 적용 범위를 확인합니다.
- 인질 HP 감소·0·화면 밖 이동, 스킬 버튼 클릭과 설명 스크롤, 다른 16:9 해상도를 확인합니다.

배경 기준점 선정은 A/B 시야를 참고합니다. 큰 카메라 변경 뒤에는 카메라 표시만 확인하지 말고 [동적 배경 후보 검사](03_동적전투배경_기술문서.md)도 다시 검증해야 합니다.

# 전투씬 개편과 탐사 외형 개선 종합 리포트

작성일: 2026-10-13 · 1차 초안 · [문서 안내](README.md)

현재 테스트베드는 탐사씬의 외형을 가져와 전투 공간을 동적으로 구성하고, 공통 쿼터뷰와 전투 UI를 적용하는 기본 경로를 갖추었습니다. 아놀드의 이동에 따라 조우 위치가 달라져도 사전에 위치별 완성 배경을 제작하지 않고 대응하는 것이 핵심 성과입니다. 사용자는 이 기본 로직이 필요한 스펙을 충족한다고 판단했으며, 다음 단계는 데코레이션 확장입니다. 이는 모든 지형·기기·전투 분기에 대한 출시 검증 완료를 뜻하지 않습니다.

## 시작 배경과 해결하려던 문제

초기 목표는 탐사 주변 공간을 별도 전투씬으로 가져오면서 읽기 쉬운 전투 구도를 만드는 것이었습니다. 추가 배경 제작 부담을 줄이기 위해 탐사 외형을 재사용하고 필요한 디테일을 규칙으로 보강하는 방향으로 진행했습니다.

카메라 검증은 `JC_BattleTestScene`에서 먼저 진행했습니다. 아군 뒤에서 적을 바라보는 F6, 반대편 F7, 기존 뷰 F8을 제공하고 모든 구도 변경을 선형 보간했습니다. F8은 뒤쪽 대상 선택을 도울 수 있는지 비교하기 위한 수동 시험 수단입니다. 스킬 타겟 선택에 맞춘 자동 카메라 전환은 현재 완료 범위가 아닙니다.

처음 탐사 외형을 전투 크기로 확대했을 때에는 좁은 도로와 전면 건물, 가까이서 드러나는 낮은 지형 디테일이 문제가 됐습니다. 탐사 이동용 셀의 크기를 전투 진형의 규칙으로 해석하지 않고, 외형만 활용한다는 기준을 명확히 했습니다. 이후 보도·연석·야지 경계와 수면 표현을 개선하고 그 결과를 탐사에서도 재사용하는 구조로 확장했습니다.

## 작업 흐름과 채택한 결과

| 단계 | 요구와 관찰 | 채택한 결과 |
|---|---|---|
| 고정 쿼터뷰 시험 | 앞뒤 캐릭터 겹침과 원근 축소를 비교할 필요 | F6/F7/F8, 선형 전환, 프리카메라 캡처, 저장·로드 프로필, 원근 강도 |
| UI 레이아웃 | 하단 HUD가 전장을 차지함 | 캐릭터 정보·스킬·설명을 좌측에 세로 배치, 어두운 반투명 패널, 턴 순서는 상단 중앙 |
| 고정 인카운터 배경 시험 | 대표 장소와 소품이 포함된 사례가 필요 | Main_1-1, Main_1-2, Main_2-2를 시험 프리셋에 추가. 첫 검토는 Main_1-2 |
| 외형 품질 개선 | 원본을 확대하니 보도·야지·물 경계가 부족 | 재사용 도로 부품 및 탐사 오버레이 개발, 원본 보도 질감 보존 |
| 경계 반복 수정 | 연석이 띄엄띄엄 보이고 Z-fighting과 모서리 각짐 발생 | 연속 블록, 면 분리, 모따기·라운딩, 안쪽 교차점 채움, 낮은 야지 연석 |
| 흙길 진입로 | 흙길이 도로로 튀어나옴 | 연석 폭 안에서 도로색→흙길 전이, 입구 양끝 둥근 블록, 일반 연석과 색·높이 통일 |
| 수로와 수면 | 타일별 흰 패턴이 반복되고 흐름이 잘 안 보임 | 도심형 호안, 교량 하부 시각적 물길, 월드 좌표 기반 연속 물결, 별도 음영 가시성 |
| 아놀드의 이동 조우 | 고정 장소만으로는 추적자 전투를 처리할 수 없음 | 실제 파티·적 위치 입력, 주변 공간 검색, 원형을 유지한 배경 복제 |
| 실제 게임 연결 | 시험 장면만으로는 전투 진행을 보장할 수 없음 | 기존 조우·대화·전투·복귀 경로에 표시 연결부 삽입, 실제 아놀드 전투 분기 검증 |
| 공통 뷰 확대 | 일반 이벤트·점령전에도 같은 뷰 필요 | 본게임 공통 카메라·HUD, 튜토리얼은 카메라만 연결, 신규 인질 HP바 |
| 1차 배포 | 기획팀의 실제 플레이 피드백 수집 | Windows 64비트 빌드, 기본 1920×1080, 기존 11개 씬 구성 유지 |

이 표는 요구사항의 진행 순서입니다. 초기 고정 배경 추출·도로 보정 방식과 현재 아놀드 동적 방식이 동일하다는 의미는 아닙니다. 현재 동적 방식은 원본 도로를 늘리거나 건물을 밀어내지 않고, 주변 기준점·축·전체 확대 배율을 고릅니다.

## 현재 시스템의 책임 분리

| 계층 | 역할 | 주요 책임 |
|---|---|---|
| DH 탐사 | 레벨 배치, 타일·격자, 파티·적 이동, 조우와 이벤트 입력 | 실제 게임 상태의 원천 |
| JC 탐사 드레싱 | DH 생성 외형을 읽어 시각 메시·재질을 보강 | 원본 표현 복원, 디테일 프로필, 임시 자원 관리 |
| 전투 연결 | 참가자와 이벤트 컨텍스트를 유지하며 장면 전환 | DH·JC 기존 연결부와 새 표시 준비 호출 |
| JC 동적 배경 | 조우 위치 수집, 후보 선택, 외형 복제, 도로·자연 소품 보강 | 전투 배경과 그 수명 관리 |
| 기존 전투 시스템 | 참가자·진형·스킬·피해·보상·복귀 | 주로 ASB 전투 및 DH 진행 로직 |

폴더가 DH라고 모든 줄이 DH만 작성한 것은 아닙니다. 기존 조우 연결 코드에도 JC 수정이 있고, 인질 HP 표시에는 ASB 코드에서 JC 프로필을 읽는 의존성이 있습니다. 기능 이식 시 변경된 호출부까지 확인해야 합니다.

## 확정한 시각 기준

- 보도는 탐사 원본의 색과 질감을 유지하고 과도한 블록 음영·엠보싱을 줄입니다.
- 연석은 연속된 밝은 회색 석재 블록으로 표현합니다. 지면과 높이가 비슷한 풀밭에는 낮은 연석을 사용합니다.
- 보도 라운딩은 외곽 형상을 재구성하여 구현합니다. 같은 높이의 원본 면 위에 단순히 겹쳐 놓지 않습니다.
- 탐사 횡단보도는 흰색으로 표시합니다. 전투 중앙선은 전투 크기에 맞춘 황색 점선이며 주차장에는 새 중앙선을 추가하지 않습니다.
- 자연 소품의 추가 산포는 전투 배경에만 적용합니다. 탐사씬의 향후 가로수·소품 배치는 별도 후속 범위입니다.
- 수면은 카툰풍의 잔잔한 움직임입니다. 실제 유체 시뮬레이션이 아니며, 세부 폴리싱은 보류 상태입니다.
- 고저차·엄폐·기습 보너스 등 새로운 전투 규칙은 이번 외형 작업에 포함하지 않습니다.

## 아놀드 전투가 주차장에서 보일 수 있는 이유

아놀드의 실제 조우에는 위치별 완성 배경 프리셋을 사용하지 않습니다. 다만 파티 위치를 중심으로 주변 8유닛 안의 도로 후보를 평가합니다. 일반 도로와 주차장을 의미적으로 분리하지 않고 공간·장애물·F6/F7 시야와 확대 비용을 함께 검사하므로 가까운 주차장이 선택될 수 있습니다.

이 현상은 “프리셋으로 이동했다”는 증거가 아닙니다. 또한 현재 알고리즘은 원래 위치가 불가능할 때만 이동하는 엄격한 우선 규칙도 아닙니다. 거리와 필요한 확대 배율을 합산해 더 낮은 점수의 후보를 택합니다. 같은 지역의 여러 조우가 같은 넓은 공간을 선택할 수 있습니다. 특정 스크린샷에서 탈락한 정확한 조건은 당시 로그나 재현으로 확인해야 합니다.

## 기본 완성과 남은 범위

기본 완성으로 보는 범위는 동적 입력, 장소 선택, 주변 외형 재사용, 공통 카메라·UI, 실제 아놀드 조우 경로와 기본 전투 진행입니다. 앞으로의 데코레이션은 이 경로 위에 확장합니다.

남은 범위는 다음과 같습니다.

- 더 풍부한 전투 데코레이션과 탐사 소품의 안정적인 전달.
- 장소 유형 구분, 도로 유지 선호, 필요할 경우 후보 탈락 사유의 상세 로그.
- 턴 획득·스킬별 다이나믹 카메라, 타겟 선택 피드백에 따른 개선, UI 리소스 최종 제작.
- 수면 품질·목표 기기의 메모리와 프레임 성능·다양한 화면 크기 실기 검증.
- 점령·본부 이벤트 전투의 명시적인 배경 분류. 현재 예외 경고를 거쳐 기존 배경으로 보이는 경우가 있어 의도한 사양과 구현을 구분해야 합니다.
- 튜토리얼 종료 관리자 누락, 적 리깅 누락 등 배경 작업과 별개의 잔여 항목. 상세 상태는 [검증과 인수인계](05_검증과인수인계.md)에 있습니다.

## 팀 공유 시 주의할 버전 차이

2026-10-12 배포 폴더의 빌드는 이후 수정한 셰이더 4개와 구형 스킬 버튼 참조 복구를 아직 포함하지 않습니다. 프로젝트에서 수정됐다는 사실과 팀이 실행하는 바이너리가 갱신됐다는 사실을 혼동하지 마세요. 새로운 피드백에는 빌드 날짜, 조우 전후 화면, 가능하면 `Player.log`를 함께 남기는 것이 좋습니다.

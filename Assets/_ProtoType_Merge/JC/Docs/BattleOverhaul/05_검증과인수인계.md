# 검증 기록과 인수인계

확인일: 2026-10-13 · JC_Testbed 작업 트리 기준 · [문서 안내](README.md)

## 이번 문서의 검증 수준

이번 작업은 현재 코드·설정과 기존 작업 기록을 대조해 문서화한 작업입니다. 새 플레이 테스트나 빌드 실행을 하지 않았습니다. 아래 과거 성공 기록은 당시 버전의 해당 경로를 검증한 것이며, 모든 현재 변경을 포함한 전수 회귀 테스트를 대신하지 않습니다.

팀에 결과를 전달할 때에는 다음 네 상태를 구분합니다.

| 상태 | 의미 |
|---|---|
| 코드 확인 | 구현과 연결을 읽어 동작 의도를 확인 |
| Editor 확인 | 에셋·컴포넌트·컴파일·정적 표시 확인 |
| 플레이 확인 | 특정 입력으로 해당 실행 경로 확인 |
| 배포 실행 확인 | 빌드된 실행 파일에서 실행 경로 확인 |

## 과거 검증에서 확인한 범위

### 아놀드 실제 조우

[초기 실전 연결 기록](../JC_Arnold_LiveEncounter.md)에는 적 턴 이동을 통해 아놀드가 파티에 접근하고 실제 전투로 들어간 테스트가 있습니다. 시험용 배경 프리셋만 여는 테스트와 구분됩니다. 당시 파티 `(11,7)`에 접근하는 적 이동과, 조우 위치에서 다른 기준점으로 이동한 생성 보고가 기록되었습니다.

자동 전투 패배 후 복귀, 테스트 중 능력치를 높인 승리 분기, 도주·이후 본부 관련 처리가 각각 확인되었습니다. 능력치를 올린 승리 검증은 **승리 후 처리 검증이며 밸런스 검증이 아닙니다.** 저장 데이터 백업 복원과 생성 자원 정리도 당시 기록에 포함됩니다. 대화 콜백 교체 시점 문제와 임시 텍스처 수명 문제는 이 과정에서 수정되었습니다.

### 배경 위치 검증

초기 대표 위치와 추가 위치 묶음으로 후보 선정·외형을 검토했고, 두 번째 10곳의 A/B 스크린샷 모음은 다음 로컬 산출물에 있습니다.

[두 번째 10곳 스크린샷 모음](C:/Dev/_scratchpad/arnold-cf8fb60bd4/TenLocations2/index.html)

이 산출물은 과거 상태의 증거입니다. 이후 카메라·배경·차선·소품 변경까지 같은 결과로 검증되었다고 간주하면 안 됩니다. 팀에 전달할 때에는 HTML만이 아니라 참조 이미지도 함께 전달해야 합니다. `_scratchpad`는 배포용 문서 저장소가 아니므로 장기 보관이 필요하면 팀의 검증 자료 위치로 별도 이관합니다.

### 일반 이벤트와 인질

기존 기록에는 Main_1-2의 BE006, Main_2-2의 BE122 실제 대화·자동 전투 승리 확인이 있습니다. 인질 바는 별도 시험 입력에서 체력 50→30, 표시 비율 0.6, 체력 0 상태를 확인했습니다. 실제 모든 이벤트의 인질 배치와 모든 화면비를 검증했다는 뜻은 아닙니다.

### 은행·빌런 본부: 과거 해석의 정정

초기 직접 시험에서 수비 편성 ID가 카탈로그와 맞지 않는 결과를 보고 점령전 자체가 막혔다고 해석한 부분은 실제 플레이 흐름과 구분해야 합니다.

- 1구역 은행은 이전 플레이 결과에 따라 대화 선택지가 달라지고 BE002·BE003·BE004 등 해당 전투로 진입합니다. 수비 객체의 ID를 직접 호출하는 시험은 이 선택 과정을 재현하지 못합니다.
- 2구역 빌런 본부 역시 실제 대화의 최초·재시도 경로를 거쳐 BE490을 시작하는 연결이 있으며 현재 카탈로그에 대응 편성이 있습니다.
- 과거 테스트 중 임시 수비 ID를 넣어 연 시험은 시험용 입력이지 실제 점령전 진입이 잘못되었다는 근거가 아닙니다.

현재 남은 문제는 **점령전의 배경 정책을 명시적으로 분류하는 것**입니다. 기존 배경이 보였더라도 동적 생성 실패 후 복귀한 결과인지, 점령전으로 정상 분기한 결과인지 로그와 컨텍스트로 구분해야 합니다.

### 수면

[수면 기술문서](../JC_CanalWater_Technical.md)의 흐름 지도·공통 재질·다리 아래 통과·Collider 보존 수치는 당시 검증 장면의 결과입니다. 고정 맵 상수나 모든 실행에서 동일한 숫자가 아닙니다. 현재 사용자가 Inspector에서 조정한 결과를 우선하며, 과거 초기값으로 프로필을 덮어쓰지 않습니다. 세부 물결 폴리싱은 사용자 합의에 따라 보류했습니다.

## 배포 빌드와 현재 소스의 차이

2026-10-12 배포 산출물은 `C:/Dev/Builds/Testbed_Build/Orora.exe`입니다. 기록상 Windows 64비트 Mono, 비개발 빌드, 1920×1080 기본 해상도와 FullScreenWindow 설정입니다. 빌드 성공, 오류 0건·경고 45건, 소요 약 71.2초, 약 3.23GiB가 기록되어 있습니다.

당시 실행 파일 구성은 확인했지만 이 기록만으로 실행 파일을 실제 구동해 모든 경로를 검증했다고 할 수는 없습니다. 같은 16:9 비율의 해상도 지원도 실제 환경별 플레이 검증이 필요합니다.

이후 일부 경고를 고쳤으므로 **현재 소스와 기존 배포 폴더는 동일한 상태가 아닙니다.** 특히 아래 셰이더 4건과 스킬 버튼 3건 수정이 기존 배포 빌드에 반영되었다고 안내하면 안 됩니다.

| 분류 | 조사 결과와 현재 상태 |
|---|---|
| JC 셰이더 4건 | `TWO_PI` 중복 정의와 `pow` 입력 범위 관련 수정. 별도 검증 빌드에서 확인 |
| 스킬 버튼 프리팹 3건 | Button·TMP 스크립트 참조 GUID 수정. Missing 상태 해소와 컴포넌트 확인. 기존 배포는 미갱신 |
| DataManager/CSVDataLoad 참조 4건 | 삭제된 이전 컴포넌트 참조. 정리 후보이며 이번 범위에서 수정하지 않음 |
| 튜토리얼 GameEndCanvas 1건 | 삭제된 종료 UI 컨트롤러 참조. 아래 별도 설명 필요 |
| 리깅 관련 18건 | 두 공용 적 프리팹의 리깅 참조 계열. 현재 패키지 구성과 함께 조사 필요, 수정하지 않음 |
| SkillPresentation 18건 | 빈 AnimationStateName 항목의 반복 보고. 현재 없는 VFX·연출 관련 사용자 보류 범위와 함께 검토 |
| 그 외 컴파일 경고 | 재빌드 방식에 따라 표시 여부가 달라짐. 증분 빌드에서 안 나왔다고 해결로 집계하지 않음 |

위 표는 여러 검사 단계의 결과를 함께 정리한 것이므로 숫자를 더해 최초 45건으로 해석하면 안 됩니다. 별도 검증 빌드의 44건은 Missing 26건과 SkillPresentation 18건으로 집계되었으며, 이후 스킬 버튼 3건을 수정했습니다. 최신 전체 재빌드 경고 수는 다시 산출해야 합니다. `SkillResult.Handler` nullable 관련 보완은 사용자 결정으로 보류되었습니다.

튜토리얼 GameEndCanvas 문제는 정상 튜토리얼 완료 처리와 다릅니다. 남은 조건은 턴 제한 계열이며, 정상 완료는 `TutorialCellEventController.CompleteTutorial`에서 처리됩니다. 대체 종료 관리자를 단순 부착하면 탐사 진행 데이터 초기화 등 의도하지 않은 동작을 만들 수 있으므로 DH 측 종료 정책을 먼저 확인해야 합니다.

타겟 선택은 현재 사용자가 큰 이상을 느끼지 않았으며 팀 테스트 피드백으로 개선할 계획입니다. 이 문서에서는 새 타겟 선택 개편을 완료했다고 기록하지 않습니다. 고저차·엄폐·기습 보너스도 이번 작업으로 추가된 전투 규칙이 아닙니다.

## 수정 후 회귀 테스트 절차

### 준비

1. 테스트베드 경로·브랜치·변경 상태와 Unity 연결 포트를 확인합니다. 원본 프로젝트와 혼동하지 않습니다.
2. 두 프로젝트가 공유하는 저장 데이터의 사용 여부를 확인하고 백업합니다. 다른 프로젝트에서 동시에 플레이하지 않습니다.
3. 카메라·수면·드레싱 프로필의 사용자 변경을 보존합니다. 미저장 씬을 임의 저장하거나 초기화하지 않습니다.
4. 변경된 메시가 있으면 동적 배경 공통 입력 캐시를 갱신합니다.

### 탐사 외형

JC 월드 드레싱을 켜고 끄며 원본 복원, 이동·충돌·이벤트 보존을 확인합니다. 도로-풀밭, 흙길 진입로, 볼록·오목 연석, 동일 높이 풀밭, 호안·다리 아래 수면을 확인합니다. 화면 확대와 실제 Game 카메라 양쪽에서 틈·Z-fighting·노멀·색 차이를 봅니다.

### 동적 배경

좁은 직선 도로, 넓은 교차로, 주차장 주변, 산 외곽, 수로·다리 인근을 포함합니다. 실제 조우 좌표와 선택 기준점, 이동 거리, 방향, 확대율, 실패 로그를 남깁니다. A/B 모두에서 진형 가림·잘린 지형·소품 침범·도로 표식 방향을 확인합니다.

임의 좌표 시험만으로 끝내지 말고 실제 아놀드 턴 이동→조우→전투→탐사 복귀도 확인합니다. 후보가 없는 경우 기존 배경으로 안전하게 복귀하는지 별도로 확인합니다.

### 전투 종류와 UI

Main_1-2·Main_2-2 같은 고정 이벤트, 인질 포함 전투, 은행의 활성 선택지별 경로, 2구역 본부의 최초·재시도 경로, 튜토리얼을 확인합니다. 직접 ID 호출은 보조 시험으로만 사용합니다. F6/F7/F8, 인질 체력 표시, 스킬 선택·설명·자동·배속·도주를 확인합니다.

### 종료와 배포

승리·패배·도주 후 파티 위치와 적·이벤트 상태를 확인합니다. 반복 진입으로 생성 메시·재질·RenderTexture가 누적되지 않는지 확인하고 테스트 저장 데이터를 복원합니다. 마지막으로 빌드된 실행 파일에서 1920×1080과 다른 16:9 해상도를 확인하며, 수정 후 새로 생긴 경고와 기존 보류 경고를 구분합니다.

# 월드 드레싱 베이크 도구

2026-10-13 후속 전환 · 기존 자동 갱신 방식에 대한 사용자 스펙 변경

## 정책

도로·보도·연석·진입로·호안·수면의 생성 알고리즘은 유지하고 편집기 생성 도구로 전환했습니다. 런타임은 확정된 메시·재질·흐름 지도를 로드합니다. 생성기 본체는 `UNITY_EDITOR`로 제외되며 런타임 Update나 주기적 전체 맵 검사는 없습니다.

원본이 달라지면 경고를 남기고 DH 원본을 표시합니다. **Force Baked On Mismatch**를 켜면 불일치에도 마지막 확정본을 강제로 표시합니다. 이 토글은 오류를 해결하거나 새 맵에 맞춰 보정하지 않습니다. 새로운 타일과 이전 외형이 겹칠 수 있으며, 원본 연결이 남아 있는 청크에만 숨김을 적용합니다.

미갱신 베이크는 빌드를 차단하지 않습니다. 빌드 전 검사가 경고를 출력하고, 원본 에셋 변경 경고를 런타임 카탈로그에 기록해 Player에서도 기본 원본 복귀 정책을 적용합니다. 설정 초안만 바뀐 것은 기존 확정 결과 사용을 막지 않습니다.

## 사용 순서

1. DH 맵 에디터에서 지형을 준비하고 탐사씬을 엽니다.
2. `JC_WorldDressing > JC_ExploreDetail`을 선택합니다.
3. **원본 변경 검사**로 현재 베이크와의 차이를 확인합니다.
4. 생성용 프로필을 조절하고 **드레싱 재생성 · 미리보기**를 누릅니다.
5. 결과를 확인합니다. 취소하려면 **확정 결과 표시 / 미리보기 취소**를 누릅니다.
6. 채택하려면 **베이크 확정**을 누릅니다. 결과 에셋을 저장하지만 씬을 자동 저장하지 않습니다.
7. 필요하면 **직전 확정본 복구**로 두 세대를 교환합니다.

프로필 수정은 자동 반영되지 않습니다. 미리보기 이후 설정이나 원본이 바뀌면 확정을 거부하고 다시 재생성하도록 안내합니다. 플레이 중 재생성과 베이크 확정은 금지합니다. 컴포넌트의 강제 표시와 원본/확정본 표시 전환은 검사 목적으로 사용할 수 있습니다.

프로필의 `forceBakedOnMismatch`는 다음 설치 시 초기 정책입니다. 현재 선택된 관리 컴포넌트의 동일 토글은 현재 표시를 제어합니다. 일반 생성 수치를 플레이 중 편집해도 베이크 메시·재질은 바뀌지 않습니다. 물결은 저장된 수치로 셰이더 시간에 따라 계속 움직입니다.

## 저장 구조

- `ExploreDetail/Resources/JC_ExploreDetail_Bakes.asset`: 씬 경로별 현재 확정본과 직전 확정본 경로.
- `ExploreDetail/Baked/<씬명>_<세대ID>/Bake.asset`: 버전, 원본 입력, 생성 설정 스냅샷, 생성 기록, 에셋 의존성.
- 같은 세대 폴더의 `Visuals.prefab`, 메시·재질·임시 생성 텍스처 에셋.

새 세대를 먼저 저장한 후 카탈로그 연결을 교체합니다. 저장 중 실패하면 기존 확정본은 유지합니다. 현재와 직전 세대를 보존하며 그보다 오래된 도구 생성 세대만 정리합니다. 직전본은 경로로 기록하여 런타임에서 불필요하게 함께 로드하지 않습니다.

사용자 원본 메시·재질 에셋은 수정하지 않습니다. 출력 재질은 복제 저장하고 MaterialPropertyBlock 값을 반영합니다. 원본에서 가져오는 영구 텍스처는 참조를 유지하며, 직접 생성한 흐름 지도는 에셋으로 저장합니다. 따라서 입력 텍스처 자체가 바뀐 경우에는 의존성 경고를 확인해야 합니다.

## 런타임 흐름

`LevelZoneLayoutLoader.RuntimeLayoutLoaded` 및 `LevelLoader.RuntimeLevelLoaded`를 구독합니다. DH 파일을 수정하거나 별도 맵 생성기를 만들지 않았습니다. 씬 로드와 로더 완료 이벤트는 다음 프레임의 적용 예약으로 합칩니다. DH가 이전 청크를 지연 삭제하는 동안 이전·새 청크를 동시에 검사하지 않도록 하기 위한 처리입니다. 로더 이벤트가 없는 저장된 지형 씬도 같은 초기 적용을 사용합니다.

입력 검증 → 확정 프리팹 인스턴스 생성 → 대응 원본 `forceRenderingOff` 보관·숨김 순서로 적용합니다. 맵이 명시적으로 다시 로드되면 완료 이벤트에서 다시 검증하지만, 위치나 설정을 계속 감시하는 타이머는 없습니다. 비활성화·종료 시 원래 표시 상태를 복원합니다.

## 식별과 변경 검증

Instance ID는 저장하지 않습니다. 원본 청크의 계층 이름과 같은 이름 형제의 순번으로 키를 만들고, 월드 행렬·메시 정점/노멀/UV/인덱스·재질 표시 속성 등을 지문으로 비교합니다. 교량의 배치와 Renderer Bounds도 수면 입력이므로 포함합니다.

편집기에서는 AssetDatabase로 레벨 데이터·리소스·생성기 코드의 의존 파일 목록을 수집하고, 각 원본 파일과 meta의 SHA-256 지문을 검사합니다. 텍스트 파일의 BOM·CRLF 차이는 정규화합니다. 프로젝트별 Library 임포트 해시 차이만으로 동일한 베이크가 거부되지 않도록 2026-10-14 JC 이식 과정에서 보완했습니다. 이전 임포트 해시 방식의 확정본은 재베이크하거나 강제 표시로 확인할 수 있습니다. 따라서 지형이 아직 재생성되지 않았어도 저장된 입력 에셋의 변경을 보고할 수 있습니다. 임의의 미래 DH 포맷을 자동 해석하지는 않습니다. 원본 메시를 판독할 수 없으면 구조 확인 실패로 원본 표시를 유지합니다.

현재 위치·수치는 0.00001 단위로 정규화해 비교합니다. 이보다 작은 변화를 구분하는 정밀 측정 도구가 아닙니다. 새 지형 체계나 청크 이름 규약을 도입할 때는 키와 입력 판독부를 검토해야 합니다.

## 동적 전투 연결

출력 계층 이름 `JC_ExploreDetail_Visuals`와 MeshRenderer 구조를 유지하므로 기존 동적 Capture가 확정 외형을 읽습니다. 베이크 메시에는 CPU 읽기 데이터를 유지합니다. 공통 입력 수집 메뉴는 더 이상 탐사 드레싱을 생성하지 않으며, 미확정 미리보기가 있으면 확정 또는 취소를 요청합니다.

## 1차 검증 결과와 남은 확인

편집 모드에서 원본 위치 변경 및 같은 메시의 정점 변경 감지, 불일치 시 DH 원본 복귀, 강제 표시, 베이크 누락, 직전본 복구, 프로필 초안 변경 시 확정본 유지, 비활성화 후 복원을 검증했습니다. 원본 메시·재질·Collider와 기존 프로필 설정도 보존했습니다. 저장 전후 생성 메시의 정점 배열이 일치했습니다.

동적 전투 입력 수집 및 서로 다른 세 지점의 배경 생성이 통과했습니다. Windows 64비트용 런타임 스크립트 컴파일도 성공했습니다. 의존성이 오래된 경우 빌드 사전 검사는 경고를 남기되 중단하지 않으며, 정상화 후 경고 기록이 해제되는 것을 확인했습니다.

편집기 측정 표본에서 재생성은 약 1.1초, 확정본 검사·적용은 약 71ms였습니다. 전체 게임 로딩 시간이나 실제 배포 빌드의 성능 수치는 아닙니다.

이번 전환에서는 플레이 모드를 실행하지 않았습니다. 다음 사용자 테스트에서 탐사씬 최초 진입, 구역 재로딩, 아놀드 조우 후 전투 배경, 탐사 복귀를 확인해야 합니다. 특히 실제 DH 런타임 생성 결과가 확정 당시 입력과 일치하는지, 기본 모드에서 불필요한 불일치 경고가 없는지 확인합니다. 물결은 기존 확정 수치로 계속 흐르는지 함께 확인합니다.

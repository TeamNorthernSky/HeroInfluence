# DH 맵 위에 JC 월드 드레싱을 적용하는 방법

작성일: 2026-10-13 · 1차 기술 초안 · [문서 안내](README.md)

이 문서는 DH가 생성한 탐사 맵의 이동 규칙을 유지하면서 JC 외형을 덧입히는 구조를 설명합니다. 2026-10-13 후속 요청으로 **편집기 명시적 재생성·베이크, 런타임 확정본 적용**으로 전환했습니다. 자세한 조작과 저장 정책은 [베이크 도구](06_월드드레싱_베이크도구.md)를 따릅니다. 아래 도로·경계 생성 규칙은 유지됩니다.

## 구조와 진입점

```text
DH 레벨 데이터와 타일 레지스트리
    → TileChunk 메시와 원본 Renderer 및 Collider
    → 편집기에서 명시적 재생성: 청크 형상과 재질 판독
    → 미리보기 검토 후 베이크 에셋 확정
    → 런타임 입력 검증 후 JC_ExploreDetail_Visuals 인스턴스 적용
    → 원본 Renderer.forceRenderingOff 상태 보관 후 숨김
    → 설정 OFF 또는 종료 시 원본 상태 복원과 생성 자원 해제
```

Hierarchy 관리 위치는 `JC_WorldDressing > JC_ExploreDetail > JC_ExploreDetail_Visuals`입니다. `JC_WorldDressing` 전체에는 기존 나무·색상 등 다른 기능도 들어갈 수 있습니다. 아래 복원 규약은 특히 이번 `JcExploreDetailOverlay`에 대한 것이며 월드 드레싱의 모든 컴포넌트가 같은 구현이라는 의미는 아닙니다.

| 소스 | 책임 |
|---|---|
| [JcExploreDetailOverlay.cs](../../Environment/ExploreDetail/JcExploreDetailOverlay.cs) | 자동 설치, 청크 분류, 재생성 판정, 원본 복원, 도로·보도 메시 |
| [RoadEdges partial](../../Environment/ExploreDetail/JcExploreDetailOverlay.RoadEdges.cs) | 자연 경계, 흙길 입구, 표시 블록, 곡면 노멀 |
| [Waterfront partial](../../Environment/ExploreDetail/JcExploreDetailOverlay.Waterfront.cs) | 수로 호안, 수면, 교량 하부 표시 |
| [WaterFlow partial](../../Environment/ExploreDetail/JcExploreDetailOverlay.WaterFlow.cs) | 연결 수역과 흐름 방향 지도 |
| [프로필](../../Environment/ExploreDetail/JcExploreDetailProfile.cs) | 조절 가능한 규칙과 자원 참조 |
| [에디터 연결](../../Environment/ExploreDetail/Editor/JcExploreDetailEditor.cs) | 편집 모드 갱신, Inspector, 설정 저장, 적용 위치 조회 |
| [흙길 분석기](../../Environment/ExploreDetail/Editor/JcPathEdgeAnalyzer.cs) | 타일 이미지의 진입로 범위를 설정 에셋으로 추출 |

영구 설정은 [JC_ExploreDetail_Default.asset](../../Environment/ExploreDetail/Resources/JC_ExploreDetail_Default.asset)입니다. 메뉴 `JC/환경/탐사 외형 보강 설정`으로 선택할 수 있습니다. 재사용 도로 제작 자원은 `JC/Environment/RoadDetailKit`에 있으며, 탐사 쪽은 필요한 메시·재질 참조를 프로필로 받습니다.

## 설치 조건과 수명

`Ensure(scene)`는 Resources에서 기본 프로필을 읽고 `profile.sceneNames`에 해당 씬 이름이 있는지 확인합니다. 씬 최상위의 `JC_WorldDressing`을 찾지 못하면 설치하지 않습니다. 이름이 다른 임의 오브젝트를 자동 대체 루트로 사용하지 않습니다.

해당 루트 하위의 기존 오버레이를 재사용합니다. 관리 오브젝트와 표시 인스턴스는 `HideFlags.DontSave`이며 영구 정본은 별도 베이크 에셋입니다. 플레이어는 DH 맵 로드 완료 이벤트에서 검증·적용하고, 저장된 지형만 있는 씬에는 초기 적용을 한 번 수행합니다. 편집기에서는 씬 열기·어셈블리 재로딩 후 확정본을 적용합니다.

이전의 0.4/0.5초 주기 갱신은 제거했습니다. `Refresh()`와 기존 호환 호출인 `Refresh(true)`도 확정본을 검증·적용할 뿐 메시를 생성하지 않습니다. Inspector 수치 편집은 생성용 초안에만 반영됩니다. 재생성은 편집기의 `GeneratePreview`에서만 실행합니다. 입력은 안정적인 계층 키와 실제 메시·재질 속성을 비교하며 에셋 변경은 편집기 의존성 검사로 보완합니다.

`Restore()`는 다음 순서로 정리합니다.

1. 저장해 둔 각 렌더러의 `forceRenderingOff`를 원래 값으로 되돌립니다.
2. 원본→표시 복사본 매핑을 비웁니다.
3. 생성 루트를 비활성화하고 제거합니다.
4. 소유한 메시·복제 재질·텍스처를 해제합니다.

`OnDisable`과 `OnDestroy`도 복원합니다. 미리보기 생성 실패 시에는 확정본 적용을 시도하고, 베이크 누락·입력 불일치 시에는 경고와 DH 원본 표시를 기본으로 합니다. 강제 표시 토글로 기존 베이크를 볼 수 있으며 자동 보정은 하지 않습니다.

## DH 타일을 읽는 규약

입력은 같은 씬에서 이름이 `TileChunk_`로 시작하고 MeshFilter·MeshRenderer를 가진 활성 오브젝트입니다. DH 원본 청크의 Mesh 구조를 전제로 읽기 때문에 일반적인 임의 메시 분석기가 아닙니다.

| 분류 값 | 현재 판별 조건 | 사용처 |
|---|---|---|
| 1 도로 | `_BaseMap` 텍스처 이름이 `roadTexturePrefix`, 기본 `Road_`로 시작 | 도로 재질과 경계 |
| 2 보도 | `sidewalkTexture`, 기본 `tilemap_01`이고 이름이 `_RaisedCube`로 끝남 | 보도 재구성 |
| 3 풀밭 | `grassTexture`, 기본 `tilemap_04` | 낮은 경계와 자연 전이 |
| 4 공원 흙길 | 텍스처 이름이 `ParkRoad`로 시작 | 입구 범위와 도로 연결 |
| 5 물 | `waterTexture`, 기본 `tilemap_02` | 수면과 호안 |
| 0 기타 | 위 조건에 해당하지 않음 | 기본 처리에서 제외 |

`ParkRoad`는 이 코드에서 공원 흙길입니다. 이름만 보고 자동차 주차장과 동일한 유형으로 해석하면 안 됩니다.

평면은 셀당 정점 4개, `_RaisedCube`·`_FlatCube`는 20개를 전제로 분할합니다. 첫 정점과 대각 정점으로 중심·폭·UV 범위를 구하고 월드 X/Z를 1000배 반올림한 키로 인접 셀을 찾습니다. 높이는 별도로 비교합니다. DH 청크의 정점 순서·이름·텍스처 명칭이 바뀌면 이 판독부를 먼저 검증해야 합니다.

## 도로와 보도 및 연석

도로는 원본 재질을 복제하여 미세 노멀과 입자 디테일을 추가합니다. 원본 재질 에셋을 공용으로 수정하지 않습니다. 횡단보도는 공통 전투 표면 코드의 `WhiteCrosswalk`를 재사용하므로 `JcBattleSurfaceProfile`의 셰이더 참조에도 의존합니다. 탐사 중앙선의 데포르메된 비율은 유지합니다.

보도는 높이 있는 DH 메시를 읽어 표시용 상판·외곽을 다시 만듭니다. 내부 질감은 원본 재질과 UV를 유지합니다. 연석 공간을 보도에서 분리하고 별도 서브메시로 만들기 때문에, 같은 평면에 연석과 원본 상판을 겹쳐 놓을 때 발생했던 Z-fighting을 피합니다. 코너를 깎아 비는 아래 공간에는 도로 높이의 아스팔트를 보완합니다.

외곽 곡선은 코너당 16구간으로 구성하고 `SmoothCurveNormals`로 같은 위치의 비슷한 방향 노멀을 이어 줍니다. 윗면·모따기·수직면 사이의 의도된 경계는 유지합니다. 안쪽으로 꺾이는 경우에는 양옆 보도의 높이와 대각선 지면 종류를 확인하여 교차점 연석을 채웁니다.

풀밭 경계는 도로 측 인접 관계로 생성합니다. 높이 차가 `flatBoundaryTolerance` 이내이면 `flatGrassCurbHeight`, 그보다 크면 `roadsideHeight`를 사용합니다. 높은 보도와 낮은 풀밭의 경계에는 보도 쪽 연석을 만들고, 동일 공간에 양쪽 연석을 중복 생성하지 않도록 분류합니다.

주요 조절값은 `roundSidewalk`, `sidewalkCurb`, `roadsideCurb`, `cornerRadius`, `curbWidth`, `curbBevel`, `curbBlockLength`, `jointWidth`, `curbTint`, `jointTint`입니다. 줄눈을 더 선명하게 할 때 폭과 명도를 함께 보세요. 지나치게 검은 줄눈은 부품이 떨어져 있는 듯한 인상을 줍니다.

## 흙길 입구와 자연 경계

흙길의 어느 변이 열려 있는지는 편집기 분석기가 `DH/LevelTileRegistry.asset`의 실제 `ParkRoad` 이미지를 읽어 계산합니다. 임시 RenderTexture에서 128×128 사본을 읽어 흙색 조건을 검사하고 네 변의 시작·끝을 0~1 범위로 `pathEdgeRules`에 저장합니다. 원본 텍스처의 Read/Write 설정을 바꾸지 않습니다.

한 변에 분리된 흙길 구간이 여러 개면 분석기가 실패를 알립니다. 이를 하나의 넓은 입구로 임의 합치지 않습니다. 분석 규칙이 없는 흙길에는 입구를 막는 연석을 추측 배치하지 않습니다.

현재 입구는 다음 형태를 사용합니다.

- 도로 쪽 구간은 원래 도로색을 유지합니다.
- 나머지 연석 폭 안에서 도로색→흙길로 전이합니다. `entranceRoadFraction`과 `pathApronLength`가 관련됩니다.
- 양끝 표시 블록의 중심은 풀밭·흙길 경계에 맞춥니다. 큰 라운딩과 일반 연석의 색·높이를 사용합니다.
- 연결 연석과 블록 사이에 눈에 띄는 틈을 만들지 않되, 같은 면이 포개지지 않도록 영역을 분리합니다.
- `entrancePavingTint`, `entranceMarkerHeight`는 과거 설정 호환용으로 숨겨져 있습니다. 현재 독립 색·융기 설정처럼 사용하면 안 됩니다.

원본 타일 이미지를 교체했다면 Inspector의 **흙길 타일 경계 다시 분석 → 설정 저장**을 수행하고 실제 입구 방향을 확인하세요. 색 기반 분석이므로 전혀 다른 팔레트의 이미지를 넣으면 분석 조건도 함께 수정해야 합니다.

## 수로와 교량 및 물결

`canalBanks`, `cartoonWater`, `bridgeWaterPassage`를 각각 켜고 끌 수 있습니다. 호안은 수면과 육지의 경계를 읽어 콘크리트 상단·경사·하단을 표시합니다. `bankExcludedLandCells`로 특수 구간을 제외할 수 있습니다.

다리 밑에는 양쪽 수면과 Bridge 배치 범위를 바탕으로 시각적 연결 물을 만듭니다. 도로 상판과 원본 충돌 판정은 유지합니다. 호안과 교량 표시용 메시를 바꿔도 파티가 물 위를 이동할 수 있게 되는 것은 아닙니다.

수면의 연속성은 메시를 하나로 합치는 대신, 같은 월드 X/Z 좌표·시간·머티리얼·방향 지도를 사용하는 것으로 확보합니다. 물결은 두 위상으로 흐름 좌표를 혼합하고, 큰 물결과 잔물결을 따로 계산합니다. 추가 음영 가시성을 둬 반사가 약한 구도에서도 움직임이 드러나도록 했습니다.

`waterWaveVisibility`·`waterRippleVisibility`는 밝기 음영, Strength는 기울기, Speed는 시간 변화입니다. 속도만 높여도 기울기나 가시성이 0이면 체감이 달라지지 않을 수 있습니다. 흐름과 잔물결을 모두 정지하려면 Flow Speed와 Ripple Speed를 모두 0으로 둡니다. 현재 수면은 불투명이며 실제 유체·굴절·수위 변화·교각 충돌 물보라는 없습니다. 계산식과 UV 채널 규약은 [별도 수면 문서](../JC_CanalWater_Technical.md)를 참조하세요.

## 원본 보존의 범위와 산 배치 예외

오버레이 자체는 DH의 원본 MeshFilter, 공유 재질, Collider, GridManager를 수정하지 않습니다. 그러나 **이번 작업 전체에서 DH 데이터가 한 번도 바뀌지 않았다는 뜻은 아닙니다.** 도로를 침범하던 산을 이동하는 작업은 승인된 별도 수정으로 수행됐습니다.

현재 `DH/LevelData/Zone1/A2Sector1.asset` 작업 트리에는 `Mount02` 배치가 `(23,3)`에서 `(23,2)`로 바뀐 내용이 있습니다. 따라서 오버레이를 OFF하면 돌아가는 대상은 “현재 DH 원본 데이터”이지, 산 이동 이전의 과거 씬이 아닙니다. 이 변경을 다른 브랜치로 이식할 때는 시각 오버레이와 레벨 데이터 변경을 분리 검토하세요.

## 설정과 확인 절차

1. 대상 씬 이름이 프로필의 `sceneNames`에 있고 `JC_WorldDressing` 루트가 있는지 확인합니다.
2. DH 지형이 생성된 뒤 `JC_ExploreDetail`의 상태 문자열에서 적용 청크와 경계 개수를 확인합니다.
3. Inspector의 `도로-풀밭 변경 위치` 또는 `수로 적용 위치`에서 좌표와 **보기** 버튼으로 실제 위치를 대조합니다.
4. 프로필을 조절하고 **드레싱 재생성 · 미리보기 → 베이크 확정**을 사용합니다. **설정 저장**은 초안 프로필 저장이며 베이크 확정과 별개입니다. 생성 외형의 Transform 수동 편집은 영구 설정이 아닙니다.
5. **DH 원본 표시 / 확정 결과 표시**, 컴포넌트 비활성화로 원본 복원과 중복 여부를 확인합니다. 런타임의 프로필 수치 변경은 자동 반영되지 않습니다.
6. 다음으로 실제 아놀드 전투에서 해당 외형이 복제되는지 확인합니다. 탐사에서 정상이라는 사실만으로 전투 좌표 변환 후 표시까지 보장되지는 않습니다.

## 다른 개발자가 확장할 때

새 지면 유형은 `Kind`와 청크 판독 규약부터 추가하고, 보도·야지·수로 경계 간 중복 생성 조건을 정의하세요. 기존 출력 루트 아래 메시를 늘리는 경우 `owned`에 임시 자원을 등록하고 `Restore`에서 해제되게 해야 합니다.

새 탐사 소품은 월드 드레싱의 별도 하위 그룹에서 관리하되 실제 전투 Capture 대상에 들어가는지 확인하세요. 현재 동적 Capture는 허용 루트의 MeshFilter와 MeshRenderer 중심이며, Collider·스크립트·스키닝·파티클을 통째로 복제하지 않습니다. GPU 전용 배치나 LODGroup을 새로 쓰면 별도의 전달 계약이 필요합니다. 상세 기준은 [동적 전투 문서의 데코레이션 확장](03_동적전투배경_기술문서.md#데코레이션-확장의-현재-기반과-후속-설계)에 있습니다.

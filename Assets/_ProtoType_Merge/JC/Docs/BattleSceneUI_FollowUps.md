# 전투씬 UI — 재확인 사항 및 후속 처리 보고서

최종 갱신: 2026-09-16  
대상: TmpBattleScene 중심 UI 개편 / 탐사 진입 경로 DHScene_3  
상태: 2026-09-16 사용자 요청으로 기획 피드백 6항목 구현 재개. main 동기화 후 적용·비플레이 검증 완료, 이번 재개분은 미커밋·플레이 검수 대기. 아래 별도 미해결 항목은 이번 피드백 승인만으로 자동 수행하지 않는다.

## 문서의 역할

이 문서는 UI 개편 중 확인한 기획·데이터·구현의 불일치, 연결이 없는 기능, 팀 협의 및 최종 정리 대상을 모은다. [BattleSceneUI.md](BattleSceneUI.md)는 현재 실제 구현 구조의 정본이며, 이 문서는 아직 재확인하거나 결정해야 하는 사항의 정본이다. 구현된 기능과 제안·임시 방침을 구분한다.

- 확인 대상 역할은 협의할 상대를 뜻하며, 담당자가 확정되었다는 의미가 아니다.
- 문서 등록 자체는 코드·데이터·원본 기획서 수정 승인이나 파일 삭제 승인이 아니다.
- 해결하면 항목을 지우지 않고 결정, 적용 위치, 검증 근거, 날짜를 남긴다. 보고서 완성 시에도 외부 후속 작업이 남았다면 인수자와 미해결 상태를 명시한다.
- 원본 XLSX는 읽기 전용이다. 기존 기획서보다 최신 사용자 합의를 우선하며, 문서 내 다른 사양을 자동 적용하지 않는다.
- 다른 PC에서도 읽을 수 있도록 프로젝트 파일은 저장소 기준 상대 경로를 사용한다. SVN 문서는 아래의 논리적 위치로 찾고 PC별 체크아웃 경로는 별도로 확인한다.

## 7단계 완료 경계와 이후 작업 — 2026-09-15 사용자 결정

2026-09-15: 고정 UI 1~7단계 구현이 적용되었다. 마지막 7단계는 히어로/코어 스킬의 이름·본문·분류 태그를 하단 우측에 표시하고, 사용 가능 버튼 호버 → 선택 스킬 → 선택 안내 우선순위 및 적 턴 '적 행동 중' 표시를 연결했다. 전투씬 다섯 버튼은 공용 DDOL 호버를 호출하지 않는다. 컴파일·비플레이 38항목·실제 4캐릭터 설명 렌더링을 확인했으며, 새 고정 설명의 사용자 플레이 검수가 남아 있다. 이 검수 완료와 아래 후속 데이터·팝업 작업의 완료는 구분한다.

**7단계 이후 처리할 작업:**

- 툴팁에 적합한 별도 스킬 설명 문구 작성·관리 위치·변수 치환 규칙 정리(R04). 현재 데이터 문구를 사용하는 7단계 UI 구현을 이 문구 작업 때문에 미루지 않는다.
- 소총수/방패병의 AI 문구가 3번 스킬로 들어간 이벤트 원본 데이터 정리 및 담당자를 통한 SO 재임포트·영향 확인(R11). 원본 XLSX는 현재 읽기 전용이며 이번 기록은 수정 승인이 아니다.
- 결과창·시작/턴 팝업과 결과 HUD는 구현되어 PR91에 포함되었다. 남은 플레이/기획 검수, 사용 씬 이관·미사용 오브젝트/파일 최종 정리(R09), 시각 품질·리소스 교체는 아래 목록을 유지한다.
- 데이터 버전·등급·계수·실제 스킬 결선·강화 단계·기존 전투 오류는 R01~R10의 담당 협의 사항으로 남긴다. 7단계 완료가 이 항목의 해결 완료를 의미하지 않는다.

## 현재 확정된 빌런 툴팁 방향 — 출력 사용자 확인, 텍스트 자동 크기 보완

- 스킬 선택 중 또는 공격 실행 중에는 숨긴다.
- 빌런의 이름 뒤 등급은 기준 확정 전까지 공란으로 둔다. F급이나 히어로의 랭크 계산식을 임의 적용하지 않는다.
- 표시용 스킬 슬롯은 최대 5개를 미리 배치한다. 이것이 5개 스킬의 전투 실행 구현을 뜻하지는 않는다.
- 빌런 모델/점유 셀 호버와 턴 순서의 빌런 초상화 호버에 동일한 전투 전용 툴팁을 사용한다. 아군 초상화 호버는 보류다.
- 전투 Canvas에 배치하고, 공용 SkillTooltip과 DDOL 구조는 유지한다.
- 제목 배경·구분선·HP 게이지는 기존 히어로 정보창의 자산과 구성을 최대한 재사용한다. 공용 히어로 정보창 자체를 바꾸는 권한으로 확대하지 않는다.
- Stat 아이콘은 기존 프로젝트 리소스를 사용한다. 부족한 외곽 패널·스킬 카드·임시 스킬 아이콘과 초상화 원형 마스크를 임시 PNG로 제작했다.
- 현재 확인한 전투 유닛 API를 표시 데이터의 출발점으로 삼는다. V4.0을 실제 전투에 적용할지는 R01에서 확인한다.
- 사용자 확정: 스킬 슬롯 위치는 씬에서 고정하고, 표시하는 스킬 개수에 따라 배경 높이만 코드로 조절한다. 빈 슬롯은 숨긴다. 슬롯 위치·크기를 자동 LayoutGroup이나 Scale 변경으로 덮어쓰지 않는다.

### R01. V4.0 테이블 존재와 실제 사용은 별개

**확인 사실:** [V4.0 원본](../../../../Assets/_ProtoType_Merge/ASB/Data/Excel/H.I%20알파%20전투%20밸런스%20데이터%20테이블%20V4.0.xlsx) 및 같은 이름의 Data/Tables 폴더에 SO가 존재한다. DHCsvTemplateCatalog는 SO를 캐시에 읽고 TryGetEnemyUnitTemplate / GetSkillTemplate(string) 등으로 제공한다.

저장된 [DHScene_3](../../../../Assets/_ProtoType_Merge/Scenes/DHScene_3.unity)의 enemyUnitInfoDataTable GUID는 57f54f0152ff09f46bd32397d1ca3b5e로 V3.0 EnemyUnitDataTable이다. V4.0 해당 SO GUID는 7137dee111906df43a534d802c27378e이다. 이 관찰은 저장본 기준이며 모든 실행 진입 경로를 검증했다는 뜻은 아니다.

**영향:** 툴팁만 V4.0을 직접 읽으면 실제 전투 유닛의 능력치·스킬과 표시가 달라질 수 있다.

**현재 구현:** HP는 BattleCharactor.CurrentHp / MaxHp, 공격력·방어력은 FinalStats.Atk / DEF에서 읽는다. 기준 테이블의 초기 HP를 현재 HP처럼 표시하지 않는다. 레벨·전투 중 상태 효과가 어떤 필드에 반영되는지는 실제 출력 연결 시 확인한다.

**남은 확인:** V4.0 전환 담당·시점, 실제 진입 경로의 카탈로그 참조, 스킬 설명도 실행과 같은 데이터 원본을 사용하는지. UI 개편에서 테이블 참조를 임의 전환하지 않는다.

2026-09-14 UI 연결 확인: 현재 V3.0 카탈로그의 FV20002는 원거리 사격 1개, 계수 1.0을 반환하며 2~5번은 없다. 이는 일반 카탈로그 조회 결과다. 이벤트 전투에서는 availableSkills의 명시 스킬 목록도 보충 조회하므로 표시 개수가 더 많을 수 있다(R11). V4.0 전환은 수행하지 않았다.

### R02. 이름 뒤 빌런 등급

**확인 사실:** 기획 이미지에는 F급이 있다. 확인한 일반 EnemyUnitData 및 DHEnemyUnitTemplate에는 별도 등급 필드가 없다. 기존 히어로 정보의 레벨 기반 RankUtil 사용이 빌런의 기획 기준이라는 근거는 없다.

**사용자 결정:** 등급 공간은 준비하되 내용은 공란. 확인 불가능한 값에 F급을 기본값으로 넣지 않는다.

**남은 확인:** 등급의 의미, 데이터 필드 또는 산정 규칙, 이름 문자열에 포함할지 별도 표시할지.

### R03. 적 스킬 설명 변수와 계수

**확인 사례:** V4.0 EnemyUnit 시트의 FV20002(빌런연합 소총수), 7행.

- L7 / M7 / U7: 원거리 사격, 설명의 EnemySkill1Value, 계수 1.0.
- W7 / X7 / AF7: 원거리 난사, 설명에는 EnemySkill1Value가 있으나 2번 계수는 0.6.
- 기획 툴팁 예시는 사격 100%, 난사 60%로 표시한다.

**영향:** 변수 이름대로 1번 값을 가져오면 난사도 100%가 된다. 반대로 모든 변수를 현재 슬롯의 값으로 치환하면 실제로 다른 슬롯 값을 참조하려는 설명을 잘못 표시할 수 있다. 단순한 일괄 치환으로 덮지 않는다.

**현재 코드:** DHCsvTemplateCatalog는 스킬별 description과 skillValue / skillSubValue를 전달한다. 공용 ClassSkillTooltipText는 ClassSkillValue 계열을 처리하며 EnemySkill 변수 처리를 그대로 대체하지 못한다.

**남은 확인:** 변수 표기가 오타인지 교차 슬롯 참조인지 확인하고, 원본 정정 및 SO 재임포트 담당을 정한다. 공격 계수의 백분율 표현과 고정값·회복·상태 효과의 단위를 구분한다. 이번 문서 작성에서는 원본이나 생성된 SO를 수정하지 않았다.

2026-09-14 UI 임시 처리: 같은 슬롯의 EnemySkillNValue/SubValue만 백분율로 치환한다. 교차 슬롯 표기는 **수치 확인 중**으로 표시하고 최초 경고를 남긴다. 데이터 원본과 SO는 수정하지 않았다. 이 표시가 원본 정정을 대신하지 않는다.

### R04. 최대 5스킬과 툴팁 전용 설명

**사용자 결정:** UI 슬롯 최대 5개. 최종 빌런 스킬 상한은 기획 재확인 대상.

**현재 코드:** 일반 EnemyUnit은 두 슬롯, 1구역 이벤트 전투 및 별도 4구역 데이터는 세 번째 슬롯 변환 경로가 있다. 네 번째·다섯 번째 슬롯을 화면에 배치하는 것과 데이터/실행 API를 추가하는 것은 별개다.

**레이아웃 결정:** 빈 슬롯은 숨기고, 슬롯의 고정 위치는 유지하면서 실제 스킬 개수에 따라 배경 높이만 코드로 조절한다. 최대 5개 슬롯을 씬에 미리 배치한다.

**남은 확인:** 긴 설명의 줄바꿈과 화면 경계, 데이터의 최종 최대 스킬 수, 5개 초과 데이터의 처리. 5개 초과를 발견하면 일부 스킬을 조용히 누락시키지 않고 재확인 항목으로 보고한다.

2026-09-14 구현: 5개 고정 행과 개수별 배경 높이를 배치했고 0~5개를 비플레이 검증했다. 사용자 출력 확인 후 넘침 피드백을 반영해 모든 텍스트에 최소10~기존 최대 크기의 Auto Size를 적용했다. 이름·스킬명·숫자는 한 줄, 본문은 줄바꿈하며 초과 시 말줄임한다. 내부 여백은 사방 최소2이다. 2행·5행 샘플은 확인했으나 모든 최종 설명 길이의 검증은 아니다. 6번째 슬롯 데이터가 조회되면 상한 재확인 경고를 남긴다. 긴 설명을 모두 읽어야 할 때의 별도 표시 방식은 미확정이다.

**2026-09-14 사용자 추가 확인:** 현재 원본 스킬 설명은 툴팁 문구로 부적절하여 별도의 표시용 설명을 준비할 필요가 있다. 글자 자동 축소는 넘침을 처리할 뿐 문장 구성·정보량을 개선하지 않는다. 이번 수정에서 원본 설명이나 실행 데이터는 바꾸지 않았다.

**후속:** 플레이어가 읽을 툴팁용 문구(대상·효과·조건의 간결한 설명)를 준비하고, 표시용 문구의 저장 위치/관리 담당/변수 규칙을 협의한다. 실행용 설명을 임의 요약하여 확정 문구처럼 넣지 않는다. 긴 문장을 최소 크기까지 축소하거나 말줄임하는 현재 처리를 최종 문구 작업의 대체로 보지 않는다. 자동 크기 보완은 긴 이름·스킬명·큰 숫자·긴 문장으로 비플레이 렌더 검증했으며 사용자 검수 대기다.

### R05. 공격 중 숨김의 범위와 상태 제공

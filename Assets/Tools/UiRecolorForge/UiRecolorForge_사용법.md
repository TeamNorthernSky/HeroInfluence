# UI Recolor Forge 사용법

> UI 이미지(버튼, 아이콘 등)에서 **원하는 색만 골라서** 색깔·선명함·밝기를 바꿔 주는 도구입니다.
> 그래픽 지식이 없어도 사용할 수 있도록, 개념부터 차근차근 설명합니다.

- 여는 방법: Unity 상단 메뉴 → **Tools → JC → UI Recolor Forge**
- 대상 파일: **PNG** 이미지 (투명 배경 지원)

---

## 1. 이 도구가 하는 일 — 쉬운 비유

파란 버튼 이미지가 있다고 합시다. 버튼의 파란 부분만 초록으로 바꾸고 싶은데,
버튼에는 흰 글자와 검은 테두리도 있고, 파란색도 한 가지가 아니라
**밝은 파랑에서 어두운 파랑으로 서서히 변하는 그라데이션**입니다.

- 그림판처럼 영역을 마우스로 선택해서 바꾸면 → 경계가 지저분해지고, 그라데이션이 뚝뚝 끊깁니다.
- 이 도구는 다르게 작동합니다: **"파랑 계열인 픽셀은 전부, 파랑인 정도만큼"** 바꿉니다.
  이미지의 모든 점(픽셀)을 하나하나 검사해서 "이 점은 파랑 계열인가?"를 판단하고,
  파랑 계열이면 지정한 대로 색을 옮깁니다. 그래서 그라데이션도 자연스럽게 통째로 바뀌고,
  흰 글자나 검은 테두리는 건드리지 않습니다.

이 "파랑 계열"처럼 **비슷한 색의 묶음**을 이 문서에서는 **색역**(色域)이라고 부릅니다.

---

## 2. 꼭 알아야 할 개념 3가지 — 색의 3요소

모든 색은 세 가지 성질로 나눌 수 있습니다. 이 도구의 슬라이더가 전부 이 세 가지를 조절합니다.

| 용어 | 쉬운 설명 | 예시 |
|---|---|---|
| **색상** (Hue) | 색의 "종류". 빨강이냐 파랑이냐 초록이냐 | 파랑 → 초록으로 바꾸기 = 색상을 돌리기 |
| **채도** (Chroma) | 색의 "진하기·쨍함". 낮을수록 회색에 가까움 | 쨍한 파랑 ↔ 탁한 파랑 ↔ 회색 |
| **명도** (Lightness) | 색의 "밝기" | 하늘색(밝은 파랑) ↔ 남색(어두운 파랑) |

색상은 **각도(°)로 표현**합니다. 색들이 둥근 원(색상환)에 빙 둘러 있다고 상상하세요 —
빨강에서 출발해 노랑, 초록, 파랑을 거쳐 한 바퀴(360°) 돌면 다시 빨강입니다.
"색상 반경 25°"라면 "기준 색에서 색상환 위로 ±25° 안에 있는 색"이라는 뜻입니다.

> 참고: 이 도구는 내부적으로 OKLCH라는 방식으로 색을 다룹니다. 어려운 말이지만 뜻은 단순합니다 —
> **"사람 눈에 비슷해 보이는 정도"를 기준으로 색의 거리를 잰다**는 것. 덕분에 슬라이더를 움직인 만큼
> 눈에 보이는 변화도 그만큼 일어납니다. 몰라도 사용에는 지장 없습니다.

## 3. 화면 구성

```
┌───────────────────────────────────────────────┬──────────────────┐
│ [이미지 열기][프리셋 열기][💾 프리셋 저장]      │                  │
│ [원본|결과|마스크]  줌 ──── [맞춤]             │   색역 슬롯       │
├───────────────────────────────────────────────┤   (조절 패널)     │
│                                               │                  │
│              이미지 프리뷰                      │   저장           │
│         (스포이드 켜고 클릭하면 색 픽업)         │                  │
│                                               │   배치           │
└───────────────────────────────────────────────┴──────────────────┘
```

- **원본 / 결과 / 마스크**: 프리뷰에 무엇을 보여줄지 고르는 버튼입니다.
  - 원본 = 손대기 전 이미지
  - 결과 = 조절이 적용된 미리보기 (실제 파일은 아직 안 바뀜!)
  - 마스크 = **"어디가 선택됐는지" 흑백으로 표시** — 흰색일수록 강하게 선택된 곳, 검은색은 안 건드리는 곳.
    조절이 이상할 때 여기부터 봐야 합니다. (아래 6장 참고)
- 오른쪽 패널은 위에서부터 **색역 슬롯**(무엇을 어떻게 바꿀지) / **저장** / **배치**(폴더 일괄 처리)입니다.

## 4. 빠른 시작 — 이미지 한 장 바꿔 보기 (5분)

1. **[이미지 열기]** → PNG 선택.
2. 오른쪽 슬롯의 **[스포이드]** 버튼을 누르고, 프리뷰에서 **바꾸고 싶은 색(예: 버튼의 파랑 본체)을 클릭**.
   → "기준색"이 그 색으로 설정됩니다.
3. 상단 뷰를 **[마스크]**로 바꿔서 확인: 바꾸고 싶은 부분이 하얗게, 나머지는 검게 나오나요?
   - 얼추 맞으면 통과. 안 맞으면 6장의 게이트 조절을 보세요.
4. 뷰를 **[결과]**로 돌리고, "편집" 항목에서 조절:
   - 색 자체를 바꾸려면 → **색상 회전** 슬라이더 (예: 파랑→보라, 파랑→초록)
   - 더 쨍하게/탁하게 → **채도 배율**
   - 더 밝게/어둡게 → **명도 배율**
5. 마음에 들면 **[이미지 저장 (PNG)]** — 이 버튼을 누르기 전까지는 **어떤 파일도 바뀌지 않습니다.**

---

## 5. 슬롯이란? — "무엇을 어떻게 바꿀지" 한 세트

슬롯 하나 = **"이런 색을(기준색+게이트) → 이렇게 바꾼다(편집)"** 라는 규칙 한 벌입니다.

- 슬롯은 최대 4개까지 추가할 수 있습니다. 예를 들어:
  - 슬롯 1: 파랑 본체 → 초록으로
  - 슬롯 2: 하늘색 모서리 장식 → 노랑으로
- 여러 슬롯이 같은 픽셀을 잡아도 안전하게 섞여서 적용됩니다(순서 무관, 이중 적용 없음).
- 슬롯 이름 왼쪽 **▶** 를 클릭하면 그 슬롯이 "활성 슬롯"이 되어 조절 패널이 펼쳐지고,
  **마스크 뷰도 그 슬롯의 선택 범위**를 보여줍니다.

---

## 6. 게이트 — "어디까지를 같은 색으로 볼 것인가" (가장 중요!)

게이트는 **문지기**입니다. 각 픽셀이 "선택 대상인지"를 검사하는 관문이 세 개 있고,
세 관문을 모두 통과한 정도만큼 조절이 적용됩니다. **마스크 뷰를 켜 놓고 조절하세요.**

### 6-1. 색상 반경(°) + 색상 감쇠(°)

- **색상 반경**: 기준색에서 색상환으로 몇 도까지를 "완전히 같은 계열"로 볼지.
  - 좁으면(10°) 딱 그 파랑만, 넓으면(60°) 하늘색·남색까지 잡힙니다.
- **색상 감쇠**: 반경 바깥으로 **서서히 선택이 약해지는 완충 구간**의 폭.
  - 이게 "경계 부드럽게(스무딩)"의 정체입니다. 0이면 경계가 칼같이 잘려서 그라데이션 중간에 띠가 생길 수 있습니다.
  - **경계가 지저분하면 이 값을 넓히세요.**

### 6-2. 채도 하한 + 채도 감쇠

- **채도 하한**: 이보다 채도가 낮은(=회색에 가까운) 픽셀은 선택에서 **제외**합니다.
- 왜 필요한가? **흰 글자·검은 테두리·회색 픽셀은 "색상"이 사실상 없는데**, 컴퓨터 계산으로는
  우연히 파랑으로 찍힐 수 있습니다. 이 게이트가 없으면 흰 글자 가장자리가 얼룩덜룩 물듭니다.
- **흰 글자나 테두리가 같이 물들면 이 값을 올리세요.**

### 6-3. 명도 창 게이트 (평소엔 꺼 둠)

- 켜면 "이 밝기 범위 안의 픽셀만" 선택합니다.
- 예: 어두운 남색 그림자는 놔두고 밝은 파랑만 바꾸고 싶을 때.

### 마스크 뷰 판독법

| 마스크 상태 | 진단 | 처방 |
|---|---|---|
| 바꾸려는 부분이 회색·얼룩 | 선택이 약함 | 색상 반경 or 감쇠 ↑ |
| 안 바꿀 부분(글자 등)이 희끗함 | 잘못 선택됨 | 채도 하한 ↑, 색상 반경 ↓ |
| 그라데이션 끝부분만 검게 빠짐 | 색이 기준에서 멀어짐 | 색상 감쇠 ↑ |
| 경계에 계단·띠 | 감쇠가 너무 좁음 | 해당 감쇠 ↑ |

## 7. 편집 — 색을 "어떻게" 바꿀 것인가 (2가지 모드)

### 상대(델타) 모드 — "지금 색에서 이만큼 움직여라"

- **색상 회전(°)**: 색상환에서 몇 도 돌릴지. +로 돌리면 파랑→보라→빨강 방향, −면 파랑→청록→초록 방향.
- **채도 배율/오프셋**: 진하기를 몇 배로 / 얼마나 더할지.
- **명도 배율/오프셋**: 밝기를 몇 배로 / 얼마나 더할지.
- 용도: "지금 색감에서 조금만 다듬고 싶다".

### 절대(기준→목표) 모드 — "이 색을 저 색으로 만들어라"

- **목표색**을 지정하면, 기준색이 목표색이 되도록 전체가 평행이동합니다.
  그라데이션의 밝고 어두운 관계는 그대로 유지됩니다(전부 같은 만큼 이동하므로).
- 용도: "이 버튼들의 파랑을 정확히 우리 게임의 브랜드 초록으로 통일하고 싶다".
- **폴더 일괄 처리(배치)에서는 이 모드가 핵심**입니다(8장).

## 7.5 경계 혼합 보정 — 색을 크게 바꿀 때 경계가 지저분해지면

색을 아주 크게 바꾸면(예: 밝은 파랑 → 어두운 남색) **두 색이 만나는 경계**(파랑 본체와
노란 테두리 사이 같은 곳)에 옛날 색이 띠처럼 남아 부자연스러워질 수 있습니다.

왜 그럴까요? 경계 픽셀들은 "반은 파랑, 반은 노랑"인 **혼합색**이라서, 도구가
"이건 파랑이 아니네" 하고 건드리지 않고 넘어가기 때문입니다. 본체만 어두워지고
경계의 밝은 혼합색은 그대로 남으니 이가 안 맞아 보이는 겁니다.

**「경계 혼합 보정」**을 켜면 이 경계 픽셀들을 "파랑 몇 %, 노랑 몇 %"로 분해한 뒤,
**바뀐 파랑과 그대로인 노랑을 같은 비율로 다시 섞어** 줍니다. 경계가 원본과 같은
품질로 자연스럽게 이어집니다.

사용법:
1. 슬롯 A = 바꾸려는 색(예: 파랑 슬롯)
2. 슬롯 B = 경계에서 맞닿아 있는 색(예: 노랑) — **바꿀 게 아니어도 슬롯을 하나 만들어
   스포이드로 그 색만 등록**해 두면 됩니다(편집값을 만지지 않으면 그 색은 안 바뀝니다)
3. "경계 혼합 보정" 사용 체크 → 슬롯 A/B 지정
4. 결과 뷰에서 경계를 확대해 확인. 보정이 약하면 "경계 폭"을 조금씩 올리세요.

> 참고: 색을 조금만 바꿀 때는 이 기능이 없어도 티가 안 납니다. 극단적인 변경에서만 켜면 됩니다.

### 원본부터 경계가 지저분할 때 — "다시 그리기" 노브 2개

AI가 그린 이미지는 색 경계 자체가 뭉개져 있거나 잡색이 끼어 있는 경우가 있습니다.
색을 크게 바꾸면 이 원본 결함이 더 도드라지는데, 아래 두 노브로 경계를 새로 그릴 수 있습니다:

- **잡색 억제**: 경계 픽셀 중 "두 색을 섞어서는 나올 수 없는 색"(회갈색 얼룩 등)을 지웁니다.
  0 = 원본 그대로, 1 = 두 색의 순수한 혼합만 남김. 얼룩덜룩한 잡색이 사라집니다.
- **경계 평활 반경(px)**: 경계에서 색이 섞이는 **비율의 변화**를 매끄럽게 폅니다.
  뭉개지고 들쭉날쭉한 전이가 깨끗한 그라데이션으로 다시 그려집니다. 1~2부터 시도하세요.

둘 다 경계 혼합 보정이 켜져 있어야 작동하고, 경계 구간에만 영향을 줍니다(글자·아이콘 무관).

### 색 안쪽의 잡색 정리 — 슬롯의 「색 조임」

경계가 아니라 **색 면 안쪽**에 미세하게 색이 튀는 픽셀들(AI 특유의 얼룩)은
각 슬롯의 **색 조임** 슬라이더로 정리합니다 — 그 색역에 잡힌 픽셀들의 색을
대표색 쪽으로 당겨서 산포를 줄입니다. 0.3~0.5 정도부터 시도하고,
너무 올리면 의도된 미묘한 색 변화까지 단조로워지니 눈으로 보면서 조절하세요.

## 8. 배치 — 폴더 전체를 한 번에 (AI 리소스의 미세한 색 편차까지 흡수)

### 폴더 준비

작업 폴더를 하나 만들고 이렇게 구성합니다:

```
내작업폴더/
  Source/        ← 원본 PNG들을 여기 복사 (도구는 이 폴더를 절대 수정하지 않음)
  Out/           ← 결과물이 여기 생김 (Source와 같은 파일명·구조로)
  preset.json    ← 조절값 저장 파일 (프리셋 저장 시)
  report.csv     ← 처리 결과 보고서 (자동 생성)
```

도구의 "작업루트"에 `내작업폴더`를 지정하면 됩니다.

### AI 이미지의 함정과 이 도구의 해법

AI로 생성한 버튼들은 **같은 "파랑"이라도 이미지마다 미세하게 다릅니다.**
그래서 "모든 이미지에 똑같은 조절값 적용"만 하면 결과물의 색이 제각각이 됩니다.

이 도구는 **절대 모드 슬롯**에 대해, 배치 때 이미지마다:
1. 그 이미지의 대표 파랑(**앵커**라고 부릅니다)을 자동으로 찾아냅니다.
2. "그 이미지의 앵커 → 지정한 목표색"으로 매핑합니다.

→ 원본이 미세하게 달라도 **결과물은 전부 같은 목표색으로 수렴**합니다.

### 안전장치 — 드라이런과 스킵

- **[드라이런 (리포트만)]**: 실제로 아무것도 바꾸지 않고, "각 이미지에서 앵커를 찾았는지,
  기준색과 얼마나 다른지"만 검사해서 `report.csv`로 보고합니다. **배치 적용 전에 꼭 먼저 돌려 보세요.**
- **스킵 ΔE**: ΔE(델타 이)는 "두 색이 사람 눈에 얼마나 달라 보이는가"의 수치입니다.
  어떤 이미지의 파랑이 기준색과 너무 다르면(예: AI가 보라색으로 뽑아버린 경우),
  억지로 적용하지 않고 **건너뛰고 보고서에 표시**합니다. 그런 파일만 나중에 직접 열어서 처리하면 됩니다.

### report.csv 읽는 법

| action 값 | 뜻 |
|---|---|
| `applied` | 정상 적용됨 (deltaE = 그 이미지의 색 편차 크기) |
| `applied-relative` | 상대 모드 슬롯이라 그대로 적용됨 (deltaE = 참고용 편차) |
| `applied-relative-DRIFT` | 적용은 됐지만 **원본 색이 기준색과 많이 다름** → 결과물 직접 확인 권장 |
| `applied-relative-nocolor` | 적용했지만 그 이미지엔 해당 색역이 거의 없었음 (사실상 무변화) |
| `skipped-drift` | 절대 모드: 색 편차가 "스킵 ΔE"보다 커서 건너뜀 → **직접 확인 필요** |
| `skipped-noanchor` | 그 이미지에 해당 색역이 아예 없어서 건너뜀 |
| `disabled` | 슬롯이 꺼져 있었음 |

## 10. 꼭 기억할 것

1. **슬라이더를 움직여도 파일은 안 바뀝니다.** 실제 저장은 [이미지 저장]/[배치 적용] 버튼을 눌렀을 때만.
2. **Source 폴더는 절대 수정되지 않습니다.** 결과는 항상 Out에 생기므로 언제든 다시 시도할 수 있습니다.
3. **마스크 뷰가 진단 도구입니다.** 결과가 이상하면 결과 화면을 노려보지 말고 마스크부터 확인하세요.
4. 배치는 **드라이런 → report.csv 확인 → 적용** 순서로.
5. "저장 시 미세 디더" 옵션은 켜 두세요 — 그라데이션에 줄무늬(밴딩)가 생기는 것을 막아 줍니다.

## 11. 문제 해결 (FAQ)

**Q. 흰 글자 가장자리가 변색돼요.**
→ 채도 하한을 올리세요(6-2). 글자 가장자리의 반투명 픽셀이 살짝 파랗게 섞여 있어서 잡힌 것입니다.

**Q. 그라데이션의 어두운 부분만 안 바뀌어요.**
→ 어두운 파랑이 기준색에서 색상·명도가 멀어진 것. 색상 반경/감쇠를 넓히거나,
   기준색을 그라데이션 중간쯤 색으로 다시 픽업해 보세요.

**Q. 바꾼 색 경계에 띠가 보여요.**
→ 색상 감쇠(스무딩 폭)를 넓히세요. 그래도 남으면 채도 감쇠도.
   색을 **크게** 바꾼 경우(다른 색과 만나는 경계가 지저분)라면 → **7.5 경계 혼합 보정**을 켜세요.

**Q. 배치 결과에서 몇 파일만 색이 그대로예요.**
→ report.csv에서 그 파일을 찾아 보세요. `skipped-drift`면 원본 색 편차가 큰 파일입니다.
   스킵 ΔE를 조금 올려서 재시도하거나, 그 파일만 단독으로 열어 처리하세요.

**Q. 결과 저장했는데 유니티 프로젝트에는 반영이 안 돼요.**
→ 이 도구는 의도적으로 프로젝트와 분리되어 있습니다. Out 폴더의 결과물을
   확인 후 직접 프로젝트의 원하는 위치로 복사해 넣는 것까지가 작업 흐름입니다.
